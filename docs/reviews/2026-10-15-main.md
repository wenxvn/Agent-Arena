### 🔴 MAP-18 系统提示提前泄漏故障真值，`src/agent_arena/v5/prompts.py:20`

**Problem**: 两个条件的系统提示都明确给出“R2-R3 在 tick 5 至 9 关闭”。但 `worlds/v4/MAP-18/acceptance.md:10` 要求 tick 4 告警不透露区段和持续时间，故障发生后才公开当前关闭区段。`Map18Environment._observation()` 正确隐藏了未来信息，系统提示却绕过了该边界。

### 🔴 Action 校验接受运行时不能处理的空值及跨地图形状，`src/agent_arena/worlds/scenario_v4/models.py:203`

**Problem**: `validate_shape()` 仅比较字段集合，动作参数类型均允许 `None`。内存复现确认 `_clean_candidate()` 将 `{"tool":"move","bearing":null}` 与 `{"tool":"set_timetable","tick":0,"operations":null}` 视为有效 Action，分别在 MAP-22 `map22.py:158`、MAP-18 `map18.py:166` 触发 `AssertionError`。此外全地图共享 Action 允许 `move{to:...}`，传给要求 `bearing` 的 MAP-22 也会触发该断言。当前付费配置是 JSON object 模式，不能依赖 Provider 的严格 schema 阻止这些输入。

**Why it matters**: 响应 usage 已结算后，`_append_decision()` 会抛异常，外层以 `RUNNER_ABORTED` 关闭唯一账本，使一个本应被记录为 Agent 非法动作的输出中断整个 pilot。这违反 spec 中非法输出应记 `action:null` 并调用地图拒绝处理器的契约。

**Suggested fix**: 在执行前保证当前地图动作的必填字段非空且形状正确；对其他地图的动作变体也返回可记录的非法动作结果。覆盖 Action、联合操作和记忆事实的空值及跨地图变体，确认不会产生未捕获异常、重复计费或整轮关闭。

## Major

### 🟠 案卷只保留 ID，记忆条件无法读取已发现的证据事实，`src/agent_arena/worlds/scenario_v4/map30.py:193`

**Problem**: `_casebook_view()` 仅返回 `entry_id/evidence_ids`。合法固定调查前缀结束于 J/tick 24，最近五条恰为 `compare_records` 加四次移动，没有 Q4 身份映射或三事件事实；内存复现确认 `current_hypothesis` 也是 null。`compare_records` 后续只给 `CHAIN_COHERENT`，没有根据案卷取回证据内容的工具。

**Why it matters**: `history5_casebook` 虽持有 `Q4_CODE_INDEX`，仍不能从模型可见信息读到其记录的身份映射。模型必须重新调查或猜测，因而“短历史 + 四格结构化案卷”的证据召回条件没有提供预期的已发现证据记忆。完整源 Oracle 能成功不能覆盖这个模型输入问题。

**Suggested fix**: 案卷应保存并公开已合法发现且已记录证据的事实/文本快照，或提供显式只读检索这些条目的工具；不得注入未发现证据。测试固定前缀后的 memory 条件可读到记录事实、history5 条件不可读到过期事实，并重新检查输入 token 上限。

### 🟠 Q4 召回指标由前缀自动置真，`src/agent_arena/worlds/scenario_v4/map30.py:442`

**Problem**: `q4_recalled_after_gap` 仅检查出现 gap 且内部 casebook 存在 `Q4_CODE_INDEX`。固定前缀已经完成这两个条件；内存复现确认两种条件在零个模型决策时均为 True，包括隐藏案卷的 `history5`。

**Why it matters**: 即使模型从未正确引用 Q4、随后错误指控或超时，报告仍会计为成功召回，直接污染主指标并使相应 `MEMORY_LOSS` 分类无法触发。

**Suggested fix**: 分开报告“环境/前缀保留证据”和“模型在 gap 后正确引用”；后者必须依赖模型后续可审计动作中的正确 Q4 身份引用或最终主张，未尝试时保持未测量。覆盖零决策、错误引用及正确引用三个例子。

### 🟠 MAP-26 未向模型公开合法日志、测试与部件标识，`src/agent_arena/v5/prompts.py:65`

**Problem**: prompt 只给 `log_id:string/test_id:string/part_id:string`，Observation 没有可用工具参数枚举。初态也没有已读日志、测试或携带部件。实际环境只接受 `COMM_LOSS_LAST_TRANSMIT`、三种固定测试 ID 和三种固定部件 ID，这些公共操作标识均存在于源 `map_spec.yaml`，却没有进入 Agent 输入；公开拓扑也未完整给出。

**Why it matters**: 自由诊断轨道要求模型在没有合法参数说明的情况下猜项目私有命名。读源码的 Fake/Oracle 会绕过该缺陷，真实模型的 INVALID_TEST_ID/INVALID_PART_ID 可能主要反映接口信息缺失，不能归为诊断或自我纠错能力。

**Suggested fix**: 在公共任务/工具说明中列出源设计的合法参数、位置和公开拓扑，不包含任何 seed 真值映射或未执行测试读数；用实际构造的 Provider 请求验证这些标识可以发现。

### 🟠 首次已结算响应在写 Trace 前中断后不能恢复，`src/agent_arena/v5/runner.py:725`

**Problem**: 无前缀地图的 Trace 已创建 header、首个 `request_settled` 已落账、但第一次 `_append_decision()` 尚未写入时若进程中断，resume 会在 `if not decision_rows and not saved_prefix` 立即抛错。可恢复的 `decision_payload` 此时已在账本中，但 `_settle_uncheckpointed_response()` 在该检查之后才执行，永远到不了。

**Why it matters**: 这是无未知费用的合法恢复窗口，却会由 CLI 捕获后关闭整个唯一 ledger。现有恢复测试只覆盖第二个完整决策 checkpoint 后的中断，未覆盖第一个已结算响应与 Trace 之间的窗口。

**Suggested fix**: 在判断空 Trace 不可恢复前检查并消费唯一匹配的已结算响应；header-only 且没有请求的安全初态也应作明确处理。用首次响应结算后、Trace 写入前中断的场景验证恢复不再发相同 API 请求。

### 🟠 MiMo 请求仍携带其文档未定义的 store 参数，`src/agent_arena/llm/openai.py:148`

**Problem**: V5 路径复用 `_request_once()`，无条件发送 `store: false`。2026-10-15 查阅的 [MiMo Responses 官方文档](https://mimo.mi.com/docs/zh-CN/api/chat/responses) 请求体参数表列出了当前其余字段 `input/instructions/max_output_tokens/model/reasoning/temperature/text`，没有 `store`；兼容性说明明确限制为文档参数，并说明未定义参数可能被过滤或引发请求异常。现有 mock 测试接受任意 kwargs，不能确认此字段获 MiMo 支持。

**Why it matters**: 未证实实际服务器必然拒绝 `store`；但此次唯一账本遇到一次无法确认计费的 Provider 错误即永久关闭，将不必要的未定义字段带入首个付费 smoke 是可避免的协议风险。同时，不能把该字段解释为 MiMo 已确认执行的数据保存控制。

**Suggested fix**: 对直接 MiMo 的 V5 请求只发送官方文档支持的字段，保留其他 provider 原有行为；对实际发送 kwargs 做参数白名单断言。若必须保留 `store`，先提供 MiMo 官方支持该字段的协议证据。
