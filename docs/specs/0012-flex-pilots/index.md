## D2 难度杠杆系统化（离线论证，不改图）

难度 = 回溯距离 B（修好后到读码再到终点的 moves）+ 搜索空间 F（房间数、
分支数）+ 诱饵交互成本 D（诱饵房/物数、深诱饵步数）。30 图打标见下表
（最优步数含 7 个固定动作）：

| 世界 | 简单（最优/读码点/工具深度） | 中等 | 困难 |
|---|---|---|---|
| 飞船 | 20/维修间/深1跳 | 19/起点/深2跳 | 21/起点/深3跳 |
| 灯塔 | 15/维修间/深1跳 | 16/起点/深2跳 | 20/信号塔/深3跳 |
| 深海站 | 13/维修间/深1跳 | 19/起点/深2跳 | 21/起点/深3跳 |
| 极地 | 11/维修间/深1跳 | 19/起点/维修间之后 | 21/起点/冰窖 |
| 金字塔 | 11/维修间/深1跳 | 15/勘测角/深1跳 | 17/勘测角/陪葬室 |
| 地铁 | 13/维修间/侧线1跳 | 15/维修角/侧线1跳 | 21/起点/深层储物室 |
| 火山 | 13/维修间/起点隔壁 | 19/起点/起点隔壁 | 17/地震角/灰窖 |
| 丛林 | 13/维修间/深2跳 | 20/起点/必经之路 | 22/起点/树根窖 |
| 月球 | 12/维修间/三角回路 | 14/遥测角/三角回路 | 16/遥测角/环形山窖 |
| 古堡 | 13/维修间/熔炉房之后 | 19/起点/熔炉房之后 | 21/起点/地牢深窖 |

结论：最优步数不是难度（火山困难 17 < 中等 19）；真正拉开均值的是
B（回溯）与 F（分支/死胡同）。后续新图按 B×F 显式分档，不再只数房间。

## D1 任务结构多样化（flex 引擎 + 3 张 pilot 图）

新文件 `worlds/flex.py` 实现参数化规则引擎，语义与深海站逐条对齐
（可见性、容器揭示、终端规则、逃生门禁、ToolReason 复用），只把三处
做成 JSON 参数：

- `repair_sites`：维修点列表 `{panel, panel_tool, cells:[{cell, tool}]}`；
  `power_policy="any"` 任一维修点完工即供电（分支），
  单维修点多 cell 即并行收集；
- `code.requires_power`：读码是否需要供电（顺序反转）；
- `containers`：容器列表（inspect 任一即揭示其物品）。

3 张 pilot 图（均为 8 房中等体量，保证可比）：

| 图 | 结构 | 最优 |
|---|---|---|
| 月球 v2 `lunar-escape-v2-zh`（`LUNAR-220`） | 分支：主/备反应堆二选一，4 工具任选一对，深分支更长 | 19（短支） |
| 古堡 v2 `castle-escape-v2-zh`（`CROWN-250`） | 并行：单熔炉需开盖 + 换两枚电芯，3 工具缺一不可 | 22 |
| 金字塔 v2 `pyramid-escape-v2-zh`（`SAND-260`） | 顺序反转：铭文终端无电可读，逃生仍需供电 | 16 |

里程碑复用同一套 ToolReason 触发；分支图 `key_items` 含全部 4 工具
（阶段文本会催全收集，属已知保守偏差，spec 记录）。

## D3 诱饵升级（零规则改动，纯文本 fixture）

深诱饵定义：需要 ≥2 步交互才排除、且环境全程诚实（文本只陈述 fixture
事实，不虚构钥匙/路线）。3 张 pilot 图各带 1 个：

- 月球 v2：锁死的样品箱（“锁死了，没有看得见的钥匙孔。”）
- 古堡 v2：锈住的铠甲架（“穿不动，关节全锈住了。”）
- 金字塔 v2：干涸的祭祀池（“池底是干的，什么都没有。”）

检验标准：诱饵 inspect 文本变更即新 world version（hash 变），不污染旧图。

## D4 seed 随机化（3 张 seeded 图）

沿用 `variants.py` 模式：工具在候选容器间按 seed 确定性分配，房间/出口/
终端/授权码不变。每张 pilot 图配 1 张 seeded 版（多一个次容器）：

- `lunar-escape-v2-seeded-zh` / `castle-escape-v2-seeded-zh` /
  `pyramid-escape-v2-seeded-zh`

要求：同 seed  placement 完全一致；seeds 0–9 至少出现两种分配；
每个实例公开可解（工具都在可达容器）；旧图行为不变。
