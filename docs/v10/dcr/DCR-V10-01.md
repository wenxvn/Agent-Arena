- 地图：MAP-03 最后的百步（飞船 / 困难）
- 关联：`docs/v9/maps/MAP-03-audit.md`、`docs/v9/dcr/DCR-12.md`
- 规则版本：V8 `rule_hash=ba6ee7abcbb1bf4fa915ca43a22985640b9378cd38c3483eed56f6e83ea8dad4`（`scenario_v8/maps/map03.py`，只读） → V10 `rule_hash=f061aad1ba2a852b3928e037d983a1b2f97a9519e33c930556d324dbf71bae8f`（`v10/runtime/map03.py`，`RULE_VERSION=v10.map03.1`）

- 影响面：规则 / 公开信息 / 动作集 / 指标 / 实例 seed

## 1. 原始规则（V8，只读）

- `route_tag_value` 只在读码后的一个 Observation 出现（`map03.py:93,105`），但码固定为 `K7` 且写在 `goal` 文本里（`"…与 K7 航线校准"`），词表也暗示了它；seed 无效（`del seed`）。
- V8/V9 runner 只给模型最近 5 条 `action/result/tick`，没有任何 agent-owned 记忆通道。
- EVA：运行时只在进入 V 与修天线时扣 1，退出不扣；`evidence_or_rules.yaml` 写 `consume_on: [move_D3_to_V, one_repair_action_at_V, move_V_to_D3]`。

## 2. 证据与根因

- 事实：V8 三局都没有提交过码，"远期召回"在真实数据中一次都没被测到（V9 审计 §7.4）。
- 事实：`map03.long_delay_recall_accuracy` 是 `route_calibrated` 的 0/1 重编码，与成功完全共线（`METRIC_DEFECT`）。
- 事实：码写在 goal 里，任何策略可不读码直接提交 `K7`——这是构念旁路（V9 归为 BYPASS）。
- 根因：B 公开信息（码泄露在 goal）+ C 接口（无记忆通道）+ A 规则（EVA 与文档不一致）。

## 3. 方案

| 方案 | 改动 | 是否改变构念 |
|---|---|---|
| A（采用） | seed 化码与路线；删除 goal 中的码；新增 `write_memory(facts)`；清单冷藏后封存；EVA 三处计费；新指标 | 否：恢复设计文档原意（`memory_controls.structured_memory`） |
| B | 指标改名为 `short_delay_code_copy` | 放弃长期记忆构念 |
| C | 只修 EVA | 不解决旁路 |

## 4. V10 规则

1. 预登记 6 个手工变体 `VARIANTS[seed] = (起点, 样本实验室, 航线码, 天线面板码, 遥测回执码)`；实验室在 U1/D2 之间切换，起点在 U2/XU/D3 之间切换。码与任何公开字符串（节点名、里程碑名）不重合（测试 `test_codes_do_not_collide_with_public_tokens`）。
2. 航线码只出现在首次 `read_tag` 的结果 `TAG:<code>` 与该步 Observation 的 `route_tag_value`；冷藏后 `manifest_state=sealed`，再读返回 `MANIFEST_SEALED`。
3. 读码与提交之间必经 P2 冷藏 → P3 EVA → P4 遥测；所有变体中读码到提交至少 11 个动作，超过 5 条 history 窗口。
4. `write_memory(facts=[{"key","value"}])`：1 tick，最多 3 条（同 key 覆盖、超出丢最旧），原样显示在 `agent_notes`；环境不校验内容——写错码就提交错码。
5. 天线修好后公开 `antenna_panel_code`、遥测发出后公开 `telemetry_ack_code`，与航线码同格式，作为"最近看到的码"干扰项。
6. EVA：仅 `eva_supply==3` 可从 D3 进入 V；进入、在 V 内每个动作（含被拒）、返回 D3 各扣 1；在 V 内归零失败。成功路线恰好消耗 3。
7. 返航窗 `return_window_end_tick = 最短合法完成时长 + 8`，按 seed 公开。

## 5. 预期构念影响

- 召回从"可绕过"变为必需：不读码无从得知；读码后若不写笔记，提交时码已离开 5 条窗口。
- 合法失败仍存在：EVA 浪费、冷窗、返航窗、写错笔记、提交干扰码。
- 没有新增隐藏规则；所有规则写入 `public_rules()`，供 prompt 使用。

## 8. 反例测试（`tests/test_v10_map03.py`）

- 码在全程只出现在 1 个 Observation；不在初始 Observation、goal 或公开规则中；
- 冷藏后回读 → `MANIFEST_SEALED`；读码后直接去 U2 提交 → `PHASE_OUT_OF_ORDER`；
- EVA 退出扣费、二次出舱被拒、V 内空转归零失败；
- 6 seed Oracle 与公开启发式成功，`memory_gap > 5`；三消融全部 `ROUTE_KEY_REJECTED`；
- 五态：未读码 N/A、读码后截尾 CENSORED、部分进度 VALID。

## 9. 对照结果（`python -m agent_arena.v10.baselines.suite MAP-03`）

| 策略 | 成功 | 主指标均值（召回） | 阶段完成度 |
|---|---:|---:|---:|
| Oracle | 6/6 | 1.0 | 1.0 |
| public_heuristic（读码即写笔记） | 6/6 | 1.0 | 1.0 |
| no_memory（不写笔记，提交最近可见码） | 0/6 | 0.0 | 0.8 |
| late_read（计划回读清单） | 0/6 | 0.0 | 0.8 |
| random_guess（格式正确的随机码） | 0/6 | 0.0 | 0.8 |
| legal_random（6 seed × 20） | 0/120 | N/A（从未读码） | 0.0 |

`no_memory` 与 `late_read` 的 `distractor_submitted=1`：无记忆时自然会落到最近看到的同格式码上。消融失败是因为它们缺记忆，不是硬编码判负：只要笔记里写对了码，同样的路线就能成功。
