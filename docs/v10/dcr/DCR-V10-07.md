## 1. 原状与根因（V9 证据）

- 事实：V8 三局 0/3，19 次 `record` 中 14 次 `INVALID_CASEBOOK_ENTRY`——`entry_id` 合法值只存在于 `scenario_v4/map30.py:37-42`，恰好与公开 `topic_id` 同名却未说明。
- 事实：条目↔证据的允许映射、“物证 + 证人确认成对才算完整”、`formal_accuse` 只能在天庭节点 J，三项都只在实现里；R2 决策 11 实测到近期窗口失效（5 条窗口挤出证人确认）。
- 指标偏置 1：`accusation_claim_precision` 统计最后一条 `formal_accuse` 的**动作**，不检查是否被接受——R2 在 A 被判 `COURTROOM_REQUIRED`，仍被算 2/3。
- 指标偏置 2：`q4_recall_accuracy` 只检查“人名对 + 引用了 `Q4_CODEBOOK` 这个条目名”，不要求条目真的记录过；消融 `no_casebook` 在覆盖率 0/4 时仍得 1。
- 根因：B 公开信息不足（词表/成对规则/法庭节点）+ 指标口径错。

## 2. V10 规则

1. **公开接口**：`entry_ids`（4 个候选条目）、`entry_requirements`（每个事件条目的“物证 + 证人确认”两件）、`courtroom_node`、`evidence_locations`、`npc_locations`、`recent_action_window` 的 payload（档案索引把值班代号映射到人名）。
2. **跨阶段依赖随 seed 变化**（3 个预登记案卷）：

| seed | case_label | 事件/房间依赖 | 诱饵 | 真值（密封） |
|---|---|---|---|---|
| 0 | `three_events_banquet_kitchen_tower` | 证词需本事件物证；事件 2/3 需前一条目 | 无 | M4 = MARA_VENN（Q4） |
| 1 | `rotated_rooms_dual_unlock` | 事件 2 需**本事件物证 + 事件 1 完整条目**；事件 3 需先归档事件 1 | 无 | K7 = ADA_SORREL（Q7） |
| 2 | `decoy_event_and_false_lead` | 事件 3 需事件 2 完整条目 | `EVENT_4_DECOY_STAIRS`（duty_code XX，不属本案） | D5 = BASIL_ORNE（Q2） |

3. **窗口语义公开**：近期动作窗口只保留最近 5 条事件，案卷是唯一跨窗口可引用的记忆。隐藏的只有喷发式真值（凶手人名/代号）与窗口外的具体内容。
4. **指标纠偏**：
   - `accusation_claim_precision` 只统计**被接受**的 `formal_accuse`（在 J 且链条已核对、引用完整条目、未引用诱饵）；未被接受 → `NOT_APPLICABLE`（截尾 → `CENSORED`）；
   - `q4_recall_accuracy` 要求 `Q4_CODEBOOK` 条目**真的记录过**且被引用；
   - 新增 `window_pressure_events`（因 5 条窗口过期的引用尝试次数），直接量化“长间隔召回”是否被触发。

## 4. 反例测试（`tests/test_v10_batch3.py`）

- 三个案卷的 `scenario_hash` 与 label 互不相同；seed 2 存在诱饵事件；
- Observation 公开 `entry_ids` / `evidence_locations` / `courtroom_node`，但**不含**凶手人名与代号；
- Oracle 与公开启发式 3/3 成功且 `chain_reconciled == 1`、`q4_recall_accuracy == 1`；
- `late_guess`（未入卷直接指控）的 `accusation_claim_precision` 为 `NOT_APPLICABLE`，不再给未发生的指控打分；
- `window_delay`（拿到证词后延迟 5 次无关追问再入卷）每个 seed 都触发 `window_pressure_events ≥ 1` 且覆盖率 < 1.0。

## 5. 对照结果（`python -m agent_arena.v10.baselines.suite MAP-30`）

| 策略 | 成功 | 主指标均值（条目覆盖/4） | window_pressure |
|---|---:|---:|---:|
| Oracle | 3/3 | 1.0 | 0 |
| public_heuristic | 3/3 | 1.0 | 0 |
| no_casebook（不记录） | 0/3 | 0.0 | 0 |
| late_guess（直接指控） | 0/3 | 0.0 | 0 |
| evidence_shuffle（事件主张顺序打乱） | 0/3 | 1.0 | 0 |
| window_delay（延迟入卷） | 0/3 | 0.25 | 1 |
| legal_random（3 seed × 20） | 0/60 | 0.0 | 0 |

`evidence_shuffle` 覆盖率 1.0 但成功 0/3，说明“链条完整”与“指控正确”是两个可分离的量；`window_delay` 是唯一触发 `window_pressure` 的策略，把“长间隔召回”从推断变成可复算的观测量。
