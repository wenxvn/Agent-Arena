## 1. 原状与根因（V9 证据）

- 事实：`detour_shortcut`（纯绕行，15 决策）与 `no_phase_wait`（盲撞，14 决策）**都成功**，`no_phase_wait` 的 `high_tide_entries=7`。
- 事实：V8 R0 全程没走 `S_G` 一次（`crossing_attempts=0`），核心机制零触发。
- 根因：A 规则（盲撞只花 1 tick，失败也推进相位，最多 4 次必然撞开；绕行与直行成本接近）+ 指标（`earliest_safe_crossing_delay` 在未走 S_G 时为 None；没有任何量度区分“早点亮”与“刚好点亮”）。

## 2. V10 规则

1. **6 个预登记实例**（周期 / 初始相位 / 截止 / 绕行长度）：`(6,2,15,无)`、`(5,3,15,无)`、`(7,4,17,有)`、`(6,0,15,无)`（唯一“开局即安全相位”的对照实例）、`(5,3,15,无)`、`(7,2,17,有)`。
2. **盲撞要付代价**：非安全相位尝试 `S_G` → `TIDE_WINDOW_CLOSED`，耗 **3 tick** 并被潮水推回原侧；相位随耗时推进。因此“撞不开就再撞”在紧截止下不再可行。
3. **绕行完整保留**：T—B1—…—B4—D—G 六（或七）段海岸路仍然合法，但固定消耗 15（17）tick；`deadline` 就设为该值，所以绕行路线的时间余量恒为 0–2。
4. **主指标改为时间余量** `deadline − 点亮 tick`（失败 = 0，截尾 = `CENSORED`）；`window_hit_rate`、`high_tide_entries`、`wait_ticks`、`detour_edges` 作为次指标/护栏。

## 4. 对照结果（`python -m agent_arena.v10.baselines.suite MAP-04`）

| 策略 | 成功 | 时间余量逐 seed | 说明 |
|---|---:|---|---|
| Oracle（真值 BFS） | 6/6 | 1 / 4 / 4 / 5 / 4 / 2 | 机制触发 6/6 |
| public_heuristic（相位算术） | 6/6 | 1 / 4 / 3 / 5 / 4 / 1 | 每个 seed 都 ≤ Oracle |
| detour_only（纯绕行） | 6/6 | 0 / 0 / 2 / 0 / 0 / 2 | **合法替代**，但余量恒低于相位路线 |
| blind_retry（盲撞重试） | 1/6 | — | 只在“开局即安全相位”的对照实例上成功 |
| excess_wait（多等整周期） | 0/6 | — | 时间余量被浪费殆尽 |
| fixed_phase_script（固定脚本） | 0/6 | — | 不读相位 |
| legal_random（6 seed × 20） | 0/120 | — | — |

要点：`detour_only` 成功 6/6 而 `blind_retry` 只 1/6——绕行是设计保留的合法替代策略，盲撞不是。`blind_retry` 的**主指标均值**（0.833）反而高于 `detour_only`（0.667），因为它在唯一成功的那局拿到了最高余量；这说明单看主指标均值会误导，报告中必须同时给出成功率与**条件余量**（DCR 与本条一致）。

## 5. 反例测试（`tests/test_v10_batch4.py`）

- 6 个 seed 的 `scenario_hash` 互不相同；Oracle 6/6 在截止内点亮且机制触发；
- 非安全相位尝试 `S_G` 耗 3 tick 且位置不变（被推回），相位推进 3；
- `blind_retry` 只在开局安全相位的实例上成功；`detour_only` 从未尝试 `S_G`（`window_hit_rate` 为 `NOT_APPLICABLE`）且余量 ≤ Oracle；
- `excess_wait` / `fixed_phase_script` 0/6。
