## 1. 原状与根因（V9 证据）

- 事实：核心规则（“恰一名祭司全真、其余逐命题反报”）**未公开**，只写在模块 docstring 与设计 YAML 里；公开侧唯一线索是标题。
- 事实：`compare_evidence` 完全不参与成功判定也不返回信息，整局可省略（`no_compare` 9 步仍开门）。
- 事实：3 种锁型 + 1 次错交容错 ⇒ 盲交两种有 2/3 概率开门；正式 seed 0 上 `blind_two_submissions` **5 步通关**。
- 根因：B 公开信息不足（规则未公开）+ C 成功判据不要求推理 + D 指标方向与构念相反（不问不比对反而拿最优或 N/A）。

## 2. V10 规则

1. **公开推理规则**：`public_rules()` 与 prompt 明写“恰一名祭司对每一条命题都如实作答，另外两人对每一条命题都反报”。
2. **开门需要相容的封存假设**：`submit_configuration` 只有当**最近一次 `compare_evidence` 的锁型候选与提交锁型一致、且该假设与全部已观察答复/档案相容**时才开门；否则返回 `NO_CONSISTENT_HYPOTHESIS` 并记一次错交。盲交不再能开门。
3. **6 个预登记实例**：锁型候选 3 或 4 种，真值 (锁型, 诚实者) 不同，档案排除项不同，**六条命题的划分方式由 seed 决定**（不是固定表），最少问数（含/不含档案）为 3–4 / 4–5。
4. **主指标** `deduction_success` 同时要求“门开 + 存在相容封存 + 问数 ≤ 最少问数”；`blind_submit_attempts` 记录没有相容封存的提交次数。
