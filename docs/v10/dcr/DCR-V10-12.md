## 1. 原状与根因（V9 证据）

- 事实：`write_memory` 完全可选——同一 DFS 导航 **0 次写记忆也 12 决策成功**（`no_memory_write`，`path_gap=4`）。
- 事实：成功判定只看 `target_visited / node / movement_steps`，从不读取 journal；图是固定的公开拓扑。
- 根因：C 成功判据不要求记忆 + A 规则（无遮蔽、无深分岔，靠 history 窗口就够）。

## 2. V10 规则

1. **遮蔽**：Observation 只给 `current_sign`（当前路标）与 `bearings`（可用方位）；**相邻节点在你走过去之前不可见**，全图不公开。`observe_signpost` 只补充当前路标的特征（用于自证记忆），不改变位置。
2. **分岔**：每个 seed 的迷宫是“主径 0..depth + 死胡同”，深度 5/6/6/7，死胡同位置与方位指派都 seed 化；`move(bearing)` 只在该方位可用时成立。
3. **跨阶段位置记忆**：必须先到遗迹 `check_goal`，再回营地 `return_to_camp`；runner 只给策略最近 **5 条** history，深度 > 5 的返程无法只靠上下文完成，`write_memory(facts)` 是唯一跨阶段通道（`agent_notes` 原样公开）。
4. 移动预算 44（Oracle 往返 2×depth ≤ 14；带死胡同探索的公开 DFS 需要 20–35）。
5. 主指标 `mission_success`（两阶段）；`route_recall`（写入路径与真实路线的前缀匹配比例）、`wasted_moves`、`memory_writes`、`goal_recorded`。

## 4. 对照结果（`python -m agent_arena.v10.baselines.suite MAP-22`）

| 策略 | 成功 | 说明 |
|---|---:|---|
| Oracle（真值最短路 + 写方位 + 反向返回） | 4/4 | 机制触发 4/4，`wasted_moves=0` |
| public_heuristic（记忆 DFS，状态笔记） | **3/4** | seed 1 因贪心方位顺序反复进入死胡同，超出决策预算 |
| no_memory_write（只用 5 条 history） | **0/4** | 全部 `MOVE_BUDGET_EXHAUSTED` |
| fixed_bearings（固定方位顺序） | 0/4 | 同上 |
| no_return（到遗迹不返程） | 0/4 | 只记录、原地观察 |
| random_walk | 0/4 | 同上 |
| legal_random（4 seed × 20） | 0/80 | — |

要点：V9 的“0 次写记忆 12 决策通关”在 V10 变成 **0/4**（只用 5 条 history 无法维持深度 >5 的返程路径）。公开启发式 3/4 是**策略弱点**（贪心方位顺序），不是旁路：它写记忆、能返程，只是探索顺序不够好；这一点如实记录。
