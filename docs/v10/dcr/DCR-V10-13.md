## 1. 原状与根因（V9 证据）

- 事实：**完全不侦察也能通关**——直接按 X→Y→Z 逐个付费试，配合低补给时回 A 补满，12 个决策成功（`no_scout`，`clue_utilization=0`）。
- 事实：H 站的三条信号在 `SIGNAL_SUPPORTS` 里全是单元素集合，花 2 点路费 + 2 点侦察就能必然确定真值，“这条线索值不值”的判断因此退化。
- 事实：真入口 `VARIANTS[(seed + 2) % 3]`，V8 三局都用 seed 0 ⇒ **恒为 Z**，三个变体只采样到一个。
- 根因：C 成功判据不要求信息（不出手也能试）+ A 规则（单站即可确定）+ D 指标（`cost_per_discovery` 在 0 发现时 N/A）。

## 2. V10 规则

1. **出手需要线索**：`investigate` 只有在（a）已 `mark` 声明候选、（b）**至少买过一条线索**、且（c）候选未被已购线索排除时才执行；否则返回 `CLUE_REQUIRED` / `MARK_REQUIRED` / `MARK_EXCLUDED_BY_CLUE` 并记 `unjustified_investigations`。逐个付费试入口的路径被消除。
2. **四个入口 × 三处侦察**：入口 X/Y/Z/W，侦察站 N（2 点，A 旁 1 步）/ R（2 点，1 步）/ H（3 点，2 步）。信号分区设计成**没有单站对所有真值都确定**：

| 真入口 | N | R | H | N+R 是否唯一 |
|---|---|---|---|---|
| X | {X,Y} | {X,Z} | {X} | 是 |
| Y | {X,Y} | {Y,W} | {Y,Z} | 是 |
| Z | {Z,W} | {X,Z} | {Y,Z} | 是 |
| W | {Z,W} | {Y,W} | {W} | 是 |

   便宜的 N+R（4 点）对四个真值都能唯一确定；H 单独（5 点含路费）只对 X/W 确定，对 Y/Z 仍二义。**线索的价格与信息量第一次真正错开**。
3. **真入口随 seed 覆盖全部四个变体**（V8 恒为 Z）。
4. 初始补给 16（V8 为 14）：最省的“N+R + 出手”方案对最远入口需要 14 点，留 2 点余量，避免把“刚好花光”当成失败。
5. 主指标 `clue_utilization`（最强单条线索缩减的候选比例）；另有 `spent_ratio`、`unjustified_investigations`、`repeated_invalid_exploration`、`ignored_counterevidence`。

## 4. 对照结果（`python -m agent_arena.v10.baselines.suite MAP-23`）

| 策略 | 成功 | 花费比 | 线索利用率 | 说明 |

| Oracle（最省识别方案） | 4/4 | 0.69–0.88 | 0.67–1.0 | X/W 用 H 单站（1.0），Y/Z 用 N+R（0.67） |
