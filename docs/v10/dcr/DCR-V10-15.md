## 1. 原状与根因（V9 证据）

- 事实：`record_constraint` **不被任何指标引用**，跳过全部记录的 15 步路线仍 `ratio=5/5`、`GATE_OPENED`——“观察与记录是两件事”这一构念在接口上不成立。
- 事实：`illegal_door_attempts` 把“未成型试排”和“错排”混在一个计数里（V9 判 `METRIC_DEFECT`）；`constraint_satisfaction_ratio` 在从未试排时也给 0/5。
- 事实：方向钉对成功不是必需的（`no_direction_nail` 18 步成功，`ratio` 上限 4/5）——V9 标为 `OPTIONAL`。
- 事实：唯一的题面（符号集/目标排列）固定，V8/V9 只跑一个实例。

## 2. V10 规则

1. **记录成为出手前提**：`set_trial_layout` 要求**至少记录过 1 条约束**；`verify_layout` 要求**至少记录过 4 条**，否则返回 `CONSTRAINTS_NOT_RECORDED`。“只读不记”（V9 的 15 步旁路）不再能开门。
2. **4 道不同的约束题**：符号集、目标排列与四条谓词的符号角色都不同；每个实例的唯一解由 24 种排列暴力筛选保证（导入时校验，恰好 1 个解）。

| seed | 符号集 | 目标排列（N/E/S/W） |
|---|---|---|
| 0 | 日/眼/芦/甲 | 甲 / 日 / 芦 / 眼 |
| 1 | 焰/镜/苇/盾 | 盾 / 焰 / 苇 / 镜 |
| 2 | 星/瞳/穗/铠 | 铠 / 星 / 穗 / 瞳 |
| 3 | 雷/珠/藤/盔 | 盔 / 雷 / 藤 / 珠 |

3. **方向钉保持 OPTIONAL**：不读它也能开门（四条房间谓词已唯一确定排列），但 `constraint_satisfaction_ratio` 上限是 4/5——按提纲要求用连续质量量而不是删掉挑战。
4. **指标口径分离**：`wrong_layout_attempts`（错排）与 `illegal_verify_without_layout`（未成型试排）分开计数；`constraint_satisfaction_ratio` / `correct_sequence` 在从未试排时是 `NOT_APPLICABLE`，不再给 0/5。

## 4. 对照结果（`python -m agent_arena.v10.baselines.suite MAP-13`）

| 策略 | 成功 | 主指标均值 | 说明 |
|---|---:|---:|---|
| Oracle（读满 5 条 → 记录 → 试排） | 4/4 | 1.0 | 20 决策，机制触发 4/4 |
| public_heuristic（文本解析 + 24 排列暴力） | 4/4 | 1.0 | 20 决策 |
| no_record（只读不记，V9 旁路） | **0/4** | N/A | 全部 `CONSTRAINTS_NOT_RECORDED` |
| no_direction_nail（OPTIONAL 消融） | 4/4 | **0.8** | 能开门，但质量上限 4/5 |
| blind_guess（3 次盲猜） | 0/4 | N/A | 错排 3 次触发容错上限 |
| record_only_nail | 0/4 | N/A | 记录不足 4 条，无法验证 |
| legal_random（4 seed × 20） | 0/80 | N/A | — |

要点：V9 的“跳过记录仍满分”被消除（`no_record` 0/4）；方向钉作为 OPTIONAL 机制**有经证实的连续质量缺口**（0.8 vs 1.0），因此既不必强行改成 FORCED，也不再是指标虚设。
