## 1. 原状与根因（V9 证据）

- 事实：接口修复后 MiMo 仍 0/1；`no_hypothesis` 消融却**成功**——测试动作是否真的缩小假设集没有被接口或指标约束住。
- 根因：C 成功判据不要求诊断（修对即可）+ D 指标（`hypothesis_table` 空转、覆盖率计入被拒诊断）。

## 2. V10 规则

1. **诊断封存是修复前提**：`seal_diagnosis(site)` 只在候选集**被测试缩成唯一站点**时才成立（否则 `DIAGNOSIS_INCOMPLETE`）；`repair(site)` 只在已封存同一站点时执行（否则 `DIAGNOSIS_REQUIRED` / `DIAGNOSIS_MISMATCH`，并记 `unjustified_repairs`）。
2. **测试必须真的缩小假设集**：每个测试按**公开分区表**（`test_partitions`）返回读数，`candidate_sites` 是初始候选与全部读数的交集；`hypothesis_reduction = (5 − 封存时候选数) / 4`，成功的局必须为 1.0。
3. **备件代价**：修错站点耗 2 tick 并浪费一个备件，两次错修即失败——保留“侥幸盲修”的合法代价。
4. **4 个预登记实例**：漏点站点、分区结构与最少测试数（1–3）都不同。

| 1 | triple_partition | S5 | 2 |
| 2 | asymmetric | S1 | 3 |
| 3 | wide_leaf | S4 | 2 |
