## 1. 原状与根因（V9 证据）

- 事实：接口修复后 0/2→2/2，需要验证“装载与燃料分配确实必需”。
- V8 里装载只要不超容量即可，油耗与载重无关——"装多少"不影响可行性，只影响趟数。

## 2. V10 规则

1. **油耗随载重上升**：`move` 的燃料消耗 = `burn_base + ceil(cargo / 2)`，`burn_base` 与容量、库存全部公开。
2. **双约束**：单次装载 ≤ `capacity` 且 ≤ `station_stock`；可以分多次装（每次多付一个决策，`load_retries` 计入）。
3. **到达判定**：燃料不足 → `OUT_OF_FUEL`（货一并损失）；到达但 `cargo < required_delivery` → `DELIVERY_SHORT`。
4. 4 个预登记实例：初始燃料、容量、库存、必需量与油耗基数都不同。

## 4. 对照结果（`python -m agent_arena.v10.baselines.suite MAP-10`）

| 策略 | 成功 | 剩余燃料逐 seed | 说明 |
|---|---:|---|---|
| Oracle | 4/4 | 1/0/1/3 | 机制触发 4/4 |
| public_heuristic（算最小可行装载） | 4/4 | 1/0/1/3 | 与 Oracle 同量级 |
| max_load（装到容量上限） | **1/4** | — | 3 个实例 `OUT_OF_FUEL` |
| underload（少装一档） | 0/4 | — | 全部 `DELIVERY_SHORT` |
| no_move | 0/4 | — | 从未出发 |
| legal_random（4 seed × 20） | 0/80 | — | — |

要点：装载量既不能“装到最满”（烧光油），也不能“少装省油”（货不够）——`max_load` 1/4 与 `underload` 0/4 一起证明“装多少”是真实决策，而不是接口细节。

## 5. 反例测试（`tests/test_v10_batch5.py`）

- 4 个实例的燃料/容量/必需量/油耗基数不同，`scenario_hash` 互不相同；
- 装载超容量 → `CAPACITY_EXCEEDED`；超库存 → `STOCK_EXHAUSTED`；
- 载重过大 → `OUT_OF_FUEL`；装载不足 → `DELIVERY_SHORT`；
- Oracle 与公开启发式 4/4；`max_load` ≤1/4、`underload`/`no_move` 0/4。
