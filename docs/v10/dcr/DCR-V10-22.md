## 1. 原状与根因（V9 证据）

- 事实：`v9_fixed` 臂**没有有效 MiMo 结果**（provider `InternalServerError` → unknown spend，按规则封账）。
- 事实：离线也没有验证“跨期库存 + 研究积分”是否真的需要平衡——V9 只有 seed 0 的单实例。

## 2. V10 规则

1. 共 30 天，每天 `slots_per_day` 个劳动槽；`assign(plan=[...])` 一次排完当天（超出槽位 → `TOO_MANY_SLOTS`）。
2. 槽位效果：`forage` 食物 +2、`repair` 站体 +2、`research` 研究 +1。
3. 每日结算：食物 −consumption、站体 −decay；**任一归零即失败**（`STARVED` / `STATION_LOST`）。
4. 研究目标设为“Oracle 可得积分”的约 90%：只顾生存（`no_research`）一定不够，只顾研究一定活不下来。
5. 4 个预登记实例：初始库存、消耗/衰减、槽位数与研究目标都不同。

## 4. 对照结果（`python -m agent_arena.v10.baselines.suite MAP-12`）

| 策略 | 成功 | 研究积分逐 seed | 说明 |
|---|---:|---|---|
| Oracle / public_heuristic（缺口优先） | 4/4 | 38/35/40/75 | 均达标，最低食物 3–4 |
| all_research | **0/4** | — | 3 个 `STARVED`、1 个 `STATION_LOST` |
| all_forage | **0/4** | — | 全部 `STATION_LOST` |
| no_research | **0/4** | 0 | 全部 `RESEARCH_SHORT`（只够活，不够研究） |
| waste_slots（每天只用 1 槽） | **0/4** | — | 库存跟不上，`STATION_LOST` |
| legal_random（4 seed × 20） | 0/80 | — | — |

要点：四类消融分别覆盖了“只研究”“只采集”“只生存”“低效劳动”四种短路，全部 0/4——这补齐了 V9 缺失的“跨期库存与研究积分确实需要平衡”的离线证据。
