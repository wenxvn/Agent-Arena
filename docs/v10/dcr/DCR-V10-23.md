# DCR-V10-23：MAP-12 `research_completion` 取值域修复（指标范围缺陷）

- 状态：`accepted_by_agent`（`agent_reviewed`）
- 类型：**指标修复**（声明范围与可取值不一致），不改规则、不改成功条件
- 地图：MAP-12 极夜三十天（极地 / 困难）
- 发现路径：`python -m agent_arena.v10.independent_check`（Batch 9 规格驱动核对）
- 关联：`docs/v10/independent-metric-check.md`、`DCR-V10-22`

## 1. 原状与根因

Batch 9 的独立核对在 MAP-12 的 4 个环境 seed 上发现同一违规：

```
map12.v10.research_completion: VALID 但取值缺失或越界 (1.09375 / 1.111111 / 1.102941 / 1.117647)
```

根因：该指标公式是 `研究积分 / 目标`，声明却沿用了默认 `valid_range=(0.0, 1.0)`。
Oracle 与公开启发式都会**超额研究**（研究积分 35–75，目标 32–68），因此合法取值可以 >1；
声明范围与真实可取值不一致，属指标定义缺陷（V9 `METRIC_DEFECT` 清单之外的漏网项）。

## 2. 修复内容

- `formula`：`研究积分 / 目标` → `研究积分 / 目标（可 >1：超额研究计入）`
- `valid_range`：`(0.0, 1.0)` → `(0.0, 3.0)`
- 其它字段（role/direction/denominator/unit）不变；**指标取值本身不变**，
  变的只是“合法区间”的声明，因此历史数值不需要重算。

**Batch 8 的 MiMo 复测全部使用旧 `schema_hash`**（`b3fc3317…`）；本修复在其之后落地，
因此 Batch 8 逐局 manifest 里记录的 `metric_schema_hash` 与当前仓库不同。这是版本化差异，
不是数据错误：V8/V9/V10-Batch8 的旧值保留，不得与新值混算或求均值。

## 4. 对照与反例测试

- `python -m agent_arena.v10.independent_check`：MAP-12 在 4 个 seed 上从“4 条违规”变为 0；
  仍保留 Oracle 6/6、消融 0/4、`legal_random` 0/80 等既有对照（`baseline-results.md`）。
- 其余 22 图的该检查不变（仍为 0 违规），确认修复没有波及别处。
- 数值口径反例：`research_points=35`、`target=32` → `research_completion=1.09375`，
  在旧声明下越界、在新声明下合法；`research_points` 与主指标 `mission_success` 不受影响。

## 5. 迁移与回滚

- 回滚：把 `valid_range` 改回 `(0.0, 1.0)`；`metric_hash` 会变回旧值。
- 影响到新局（V11）记录的 `metric_schema_hash`；Batch 8 的局不需要也不应重写。
- 同类风险提示（未发现实例，但结构相同）：凡是“比值可超额”的指标都应对照 Oracle/启发式的
  最大取值检查 `valid_range`；本次核对未在其余 22 图发现越界。
