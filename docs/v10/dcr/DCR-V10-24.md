# DCR-V10-24：公开动作契约的类型渲染（MAP-18 / MAP-28 接口假象修复）

- 状态：`accepted_by_agent`（`agent_reviewed`）
- 类型：**接口修复**（公开信息表达方式），不改任务语义、成功条件或隐藏信息边界
- 关联地图：MAP-18（P0）、MAP-28（古堡）
- 关联证据：`docs/v10/mimo-results.md`（Batch 8）、`runs/v10/mimo/episodes/V10-MAP-18-S0-p0/`、
  `runs/v10/mimo/episodes/V10-MAP-28-S0-castle/`
- 代码：新增 `src/agent_arena/v10/contract.py`；`scripts/run_v10_mimo.py` 的 `_contract()`

## 1. 原状与根因（Batch 8 证据）

| 图 | 现象 | 逐字证据 |
|---|---|---|
| MAP-18 | 3 局各 20/20 决策全部 `INVALID_ACTION_SCHEMA` | 模型输出 `{"tool":"set_timetable","tick":0,"operations":[{...},{...}]}`；`V8Action.operations` 是 `dict[str, dict]`（对象），模型给的是数组 |
| MAP-28 | seed 0 有 11 次 `INVALID_ACTION_SCHEMA` | 模型输出 `{"claims":{"person_id":...}, "citations_by_claim":{...}}`；`V8Action.claims` 是 `list[dict]`（对象数组） |

根因：MiMo runner 的公开契约只列**字段名**（`set_timetable: {operations,tick,tool}`），
没有列字段**类型**。模型“动作意图正确、结构写错”，被严格校验判为非法动作——
这属于测量接口缺陷，不是能力差异。注意：`SHAPES` 字段名与 `V8Action` 完全一致
（30 图自检 `v10.contract.unknown_fields()` 为空），问题只在**形状未公开**。

## 2. 修复内容

1. `v10/contract.py`：从公开的 `V8Action` 模型注解渲染字段类型形状，例如
   - `operations` → `{"<key>": {"<key>": <value>}}`
   - `claims` → `[{"<key>": <value>}]`
   - `cited_entry_ids` → `[<str>]`
   - `event_claims` → `[{"event_id": <str>, "time": <str>, "location": <str>, "duty_code": <str>}]`
2. runner 的 `_contract()` 改用该渲染；对**确有证据**的两图追加公开格式澄清
   （`CONTRACT_HINTS`）：
   - MAP-18：`operations` 是对象，键为列车 id，值含 `op`（四个合法值）与 `to`/`task_id`；
   - MAP-28：`claims` 是对象数组，元素为 `{"claim_id":…, "value":…}`；
     `citations_by_claim` 是 `{字段名: [证据 ID]}`。
3. 澄清只写**公开结构**：不含答案、最优动作、隐藏真值；随 prompt 一起冻结进 `prompt_hash`。

## 3. 对照与反例测试

- 单测：`tests/test_v10_batch8_contract.py`
  - 30 图 `SHAPES` 不含 `V8Action` 未知字段（防止“契约声明了不存在的字段”）；
  - 标量/列表/字典/嵌套模型四种注解渲染正确；
  - MAP-18/MAP-28 的目标形状出现在契约里；
  - 契约文本不含 `truth`/`sealed` 等窃取真值的段落。
- 真实模型对照（阶段 3，`-i2`，整图全 seed 重跑，见 `mimo-results.md`）：

| 图 | seed | 修复前（阶段 1/2） | 修复后（`-i2`） | 结论 |
|---:|---|---|---|---|
| MAP-18 | 0 | 20/20 决策 `INVALID_ACTION_SCHEMA`，`ACTION_LIMIT_REACHED`，主指标 0.0 | 13 决策，`invalid=0`，机制触发，`HEAD_ON_COLLISION`，主指标 0.5 | 接口假象消除，失败转为真实调度错误 |
| MAP-18 | 1 | 20/20 无效，`ACTION_LIMIT_REACHED` | 8 决策，`invalid=0`，`STATION_CAPACITY_EXCEEDED`，主指标 0.5 | 同上 |
| MAP-18 | 2 | 20/20 无效，`ACTION_LIMIT_REACHED` | 7 决策，`invalid=0`，`SEGMENT_CAPACITY`，主指标 0.333 | 同上 |
| MAP-28 | 0 | 11 次无效 `submit`（形状错），从未提交，预算耗尽 | 20 决策，`invalid=0`，**成功** `ALL_CLAIMS_SUPPORTED_AND_CORRECT`，主指标 1.0 | 接口假象消除 |
| MAP-28 | 1 | 预算耗尽、未提交 | 预算耗尽、未提交（`invalid=0`） | 属策略/预算，非接口 |
| MAP-28 | 2 | 预算耗尽、未提交 | 预算耗尽、未提交（`invalid=0`） | 属策略/预算，非接口 |

要点：MAP-18 三局从“动作全部非法”变为“动作合法但会撞车”，即 0/3 的旧结论
**是接口假象**；MAP-28 seed 0 从“形状错误导致从未提交”变为真实成功。
`-i2` 与阶段 1/2 的 prompt 不同，因此只作“接口修复前后”的配对描述，不称严格 A/B。

## 4. 迁移与回滚

- 回滚：删除 `CONTRACT_HINTS` 条目并把 `_contract()` 换回字段名渲染即可；
  地图运行时（`v10/runtime/*.py`）与规则 hash **未改动**，`freeze verify` 不受影响。
- 本修复不改变任何 V10 指标定义，`metric_schema_hash` 不变（MAP-12 的范围修复是另一份 DCR-V10-23）。
- 影响面：仅 MiMo 运行器 prompt 层；离线 Oracle/启发式/消融不受影响。
