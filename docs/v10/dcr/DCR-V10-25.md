# DCR-V10-25：MAP-20 冷却网络的公开接口补全（`set_flow` / `adjust_loads` / `open_bypass` 结构）

- 状态：`accepted_by_agent`（`agent_reviewed`）
- 类型：**接口修复**（把已实现的合法动作结构写进公开规则），不改任务语义、成功条件、参数与隐藏信息边界
- 地图：MAP-20 冷却网络（火山 / 中等）
- 关联：`DCR-V10-11`（规则重构）、`DCR-V10-24`（类型化动作契约）、`validation-gates.md`（MAP-20 是唯一未过 `mimo` Gate 的图）
- 规则版本：`v10.map20.1` → `v10.map20.2`；`rule_hash` `81eb7439a55e47f27e909d0399264907b4d6ec7429f9569e0c8acf44fc66d435` → `e677a0acc1d837027281f2d1be6ab0b55835861fc8ddab65a561663c1924002d`

## 1. 原状与根因（Batch 8 证据）

MAP-20 的 MiMo 三局 **56/56、56/56、56/56 全部 `INVALID_ACTION_SCHEMA`**，直接输出示例：

```json
{"tool": "set_flow", "set_flow_tenths": {"A": 25, "B": 25, "C": 10}}
```

而 `V8Action.set_flow_tenths` 是 `list[int]`。`adjust_loads`（`list[Any]`，取值为 `FULL/REDUCED/IDLE`）
与 `open_bypasses`（`dict[str, {from,to,input_tenths}]`）同样只有字段名公开、**结构未公开**。
根因两层：① DCR-V10-24 之前契约不渲染类型；② 即使渲染了类型（`[<int>]`、`[<value>]`、
`{"<key>": {"<key>": <value>}}`），三档取值集合与旁路链路名/档位这些**语义常量**仍只存在于代码里。

## 2. 修复内容（把结构写进地图自述的公开规则）

在 `Map20V10Environment.public_rules()` 增加三条（数值全部来自公开常量
`DIRECT_MAX`/`SOURCE_MAX`/`HEAT_REDUCED_FACTOR`/`BYPASS_QUANTUM`/`BYPASS_MAX`）：

1. `set_flow_tenths` 是长度 3 的整数数组，顺序 A、B、C；每项 0–25，三项之和 ≤ 60；
2. `adjust_loads` 是长度 3 的字符串数组（顺序 A、B、C），取值只能 `"FULL"/"REDUCED"/"IDLE"`，
   三者热量分别为 本 tick 热量、×0.5、0；
3. `open_bypasses` 是对象：键只能 `"AB"`/`"BC"`，值为 `{"from","to","input_tenths"}`，
   `input_tenths ∈ {5,10,15,20}`。

同时把 `scripts/run_v10_mimo.py` 中 MAP-20 的 runner 提示条目**删除**——修复必须来自地图自身，
runner 不再替地图解释接口（MAP-18/19/28 的提示保留：它们的结构由 `dict`/`list[dict]` 注解
无法推导出元素键名，属另一类缺口）。

## 3. 对照与反例测试

- **行为不变性**：`python -m agent_arena.v10.baselines.suite MAP-20` 复跑与修复前一致
  （Oracle 4/4 且机制触发 4/4、启发式 4/4、`legal_random` 0/80、四消融 0/4）。本修复只改
  文本自述，不改环境逻辑、实例或指标。
- **契约自检**：`tests/test_v10_batch8_contract.py` 的 30 图 `SHAPES` 未知字段检查仍为空。
- **真实模型复验（阶段 4，`-j2`，整图全 seed）**：

| seed | 修复前（阶段 2 `-ext`） | 修复后（`-j2`） |
|---:|---|---|
| 0 | 56/56 决策 `INVALID_ACTION_SCHEMA`，主指标 0.0 | **非法 0/56**，`decision_budget_exhausted`，主指标 0.0 |
| 1 | 56/56 无效 | **非法 0/56**，`decision_budget_exhausted`，主指标 0.0 |
| 2 | 56/56 无效 | **非法 0/56**，`decision_budget_exhausted`，主指标 0.0 |

  要点：接口假象消除（非法动作 168/168 → 0/168），MAP-20 的 `mimo` Gate 随之通过；
  模型仍未产出任何产能（主指标恒 0），这属于**策略/难度**结论，不再是接口问题。
  `-j2` 与 `-ext` 的 `rule_hash`、`scenario_hash` 与 prompt 均已变化，只作“接口补全前后”配对描述。
