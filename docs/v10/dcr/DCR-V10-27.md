## 1. 原状与根因

V8 的 MAP-05 `_reset_state` 直接 `del seed`：窗口恒为 R[15,18]/B[22,25]/W[29,35]，
通道耗时恒为 1/2/3。V10 Batch 5 的防回归确认了 `seed_effective=False`——三个 seed 是
同一个实例，“3-seed”只是重复运行。这正是 `final-report.md` 记录的 7 图缺口之一。

## 2. V10 实例

| seed | label | R | B | W | C-R / C-B / C-W | 参考完成 tick |
|---:|---|---|---|---|---|---:|
| 0 | base | 15–18 | 22–25 | 29–35 | 1 / 2 / 3 | 31 |
| 1 | early_windows | 9–12 | 16–20 | 24–30 | 1 / 2 / 3 | 25 |
| 2 | late_windows_swapped_cost | 18–21 | 24–27 | 30–34 | 2 / 1 / 3 | 33 |
| 3 | wide_middle_short_outbound | 12–16 | 20–24 | 26–32 | 1 / 3 / 2 | 30 |

- **公开**：`windows`（三个窗口时刻）、`goal` 文案随本 seed 的窗口生成（不再写死 V8 的三个窗口）；
  `scenario_descriptor()` = `{label, windows, edge_cost}`。
- **密封**：`sealed_truth()` = `{reference_completion_tick}`（Oracle 参考完成 tick，只进 hash 与 judge）。
- **未公开**：窗口内的具体最优排程；模型必须自己按窗口顺序规划并处理“一次只能供一个塔”。

## 3. 指标（`METRIC_SPECS`，6 条）

| metric | role | 口径 |
|---|---|---|
| `map05.v10.mission_success` | primary | 三束信号都在各自窗口内发出；截尾 → CENSORED，窗口错过 → VALID 0 |
| `map05.v10.window_slack_ticks` | secondary | min(窗口结束 − 实际发送 tick)，正数表示留出余量 |
| `map05.v10.effective_signals` | secondary | 窗口内发出的信号数 / 3 |
| `map05.v10.power_switches` | diagnostic | `switch_power` 次数（共享供电的调度成本） |
| `map05.v10.missed_windows` | guardrail | 窗口结束仍未发出的塔数（0–3） |
| `map05.v10.idle_ticks` | diagnostic | 已校准但仍等待窗口的 tick 数 |

`mechanism_triggered()` = 至少切换 1 次电 **且** 至少 1 束信号落在窗口内。

## 5. 反例测试

不进 Observation、Oracle 全 seed 成功且机制触发、启发式只读 Observation、四种消融全部失败、
