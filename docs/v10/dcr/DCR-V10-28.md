# DCR-V10-28：公开动作契约补充整数字段的取值区间

- 状态：`accepted_by_agent`（`agent_reviewed`）
- 类型：**接口修复**（把已有的公开约束写进契约），不改任务语义、动作集合或成功条件
- 关联：DCR-V10-24（类型渲染）、DCR-V10-27（MAP-05 原生 seed 化）、阶段 5（`-k2`）证据
- 代码：`src/agent_arena/v10/contract.py`（`_bounds` + `field_shape`）

## 1. 原状与根因

DCR-V10-24 之后契约会渲染字段**类型**（`ticks: <int>`），但不渲染 `V8Action` 上的
`ge`/`le` 约束。MAP-05 阶段 5 的真实模型局因此出现：

```
{"tool": "wait", "ticks": 17} / 16 / 15 … 9   → INVALID_ACTION_SCHEMA
```

三局非法动作分别为 5/12、0/6、9/13：模型**意图正确**（等到窗口），但数值超出 1–8 的公开上限。

## 2. 修复内容

`contract.field_shape()` 读取 pydantic 字段元数据里的 `Ge`/`Le`，把区间追加到类型后：

- `ticks` → `<int> (1..8)`
- `turns` → `<int> (1..8)`
- `day` → `<int> (1..60)`
- `tick` → `<int> (0..)`

区间来自公开的 `V8Action` 模型，不含真值、答案或最优动作。

## 3. 对照与反例测试

- `tests/test_v10_batch8_contract.py::test_contract_documents_numeric_bounds`：四个带约束字段的
  渲染断言 + MAP-05 契约里必须出现 `"ticks": <int> (1..8)`。
- 真实模型复验：阶段 5b（`-k2b`）对 MAP-05 三个 seed 重跑，比较 `invalid_actions` 与终止原因。

## 4. 迁移与回滚

- 回滚：删除 `_bounds()` 调用即恢复“只有类型、没有区间”。
- 影响面：仅 MiMo runner 的 prompt 文本（`prompt_hash` 变化）；地图、指标与离线基线不受影响。
- 阶段 5 的 3 局保留为“修复前”证据，不覆盖。
