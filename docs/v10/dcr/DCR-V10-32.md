# DCR-V10-32：为公式级复算暴露 judge 字段（MAP-03/24/26）

- 状态：`accepted_by_agent`（`agent_reviewed`）
- 类型：**judge 字段暴露 + 指标口径注解**（不改规则逻辑、不改 Observation、不改成功条件）
- 关联：`DCR-V10-26`（截尾归一）、`metric-recompute.md`
- 代码：`v10/runtime/map03.py`、`v10/runtime/map24.py`、`v10/runtime/map26.py`（各 +1~2 个
  `judge_state` 字段）、`map24.py` 的 `zero_denominator` 注解

## 1. 原状与根因

公式级复算在 24/27 图上通过，剩下的 3 张图（03/24/26）无法独立重算，原因是
`judge_state` 缺少**原始输入**：

| 图 | 缺什么 | 影响 |
|---|---|---|
| MAP-03 | 密封航线码 `route_code` | 只能看到 `submitted_answer`，无法判断是否与真实码一致 |
| MAP-24 | `bridge_used_before_collapse` | 无法判定 `assessable`（是否值得评估改路） |
| MAP-26 | 真实故障 `true_fault` 与件号映射 | 只能看到已装件与候选集，无法判断“装对” |

## 2. 修复内容

1. `judge_state()` 追加（**只进 judge 与 state_hash，不进 Observation/prompt**）：
   - MAP-03：`route_code`
   - MAP-24：`bridge_used_before_collapse`
   - MAP-26：`true_fault`、`parts`（公开件号表）
2. MAP-24 的 `replan_success.zero_denominator` 从
   `从未观察到封路 → NOT_APPLICABLE` 改为
   `从未观察到封路 → NOT_APPLICABLE（截尾 → CENSORED）`——
   与它自己的 `censored_rule`（截尾 → CENSORED）一致，也让 DCR-V10-26 的投影归一能覆盖它。

## 3. 影响与验证

- 三张图的 `rule_hash` 变化（模块源码变更）→ `scenario_hash` 与 `metric_hash`（MAP-24）更新；
  **行为未变**：Oracle/启发式/消融结果复跑一致（MAP-03 6/6、MAP-24 4/4、MAP-26 4/4）。
- 公式级复算：**24/27 图、855 次检查、0 不一致**；剩余 3 图（13/14/21）需要实现独立的
  谓词求值 / 假设一致性 / 科学分重算，属 V11 工作。
- 独立核对：27 图 × 132 seed 实例 0 违规、回放确定 27/27、seed 互异 27/27。
- 历史 MiMo 局（MAP-03/24/26）记录的是旧 `rule_hash`；新增字段不改变行为，引用时注明即可。

## 4. 回滚

删除三处 `judge_state` 新增字段并还原 MAP-24 的注解即可；规则与 Observation 从未改动。
