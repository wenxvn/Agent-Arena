# DCR-V10-36：MAP-16 原生 seed 化（单线预约与节点容量）

- 状态：`accepted_by_agent`（`agent_reviewed`）
- 类型：**实例采样**（不改规则、不改动作契约、不改成功条件）
- 关联：`DCR-V10-27/29/30/31/33/34`（同一原生 seed 化模板）、`final-report.md` §1、`validated-regression.md`
- 代码：`v10/runtime/map16.py`、`v10/baselines/map16.py`、`v10/recompute.py::_f16`、`tests/test_v10_map16.py`

## 1. 问题

MAP-16 在 V8 走 `V4MapAdapter`，绑定 V6 冻结场景 `map16_l3_original`；`Map16Environment._reset_state`
只接受 0/1/2 三个**重复标签**且状态完全相同，因此 `seed_effective=False`，V10 只能沿用 V9 并记 3-seed 缺口。

V6 另有 `map16_l1_single_train` / `map16_l2_siding_variant_a`，但它们是 L1/L2/L3 **难度变体**；
把它们当 seed 会混淆“实例采样”与“难度递进”，因此**不采用**。

## 2. 处理

不修改 `src/agent_arena/worlds/scenario_v4/map16.py`。该环境的构造函数本来就公开了
`start_positions` / `goals` / `sidings` / `step_limit` 等参数（V6 用它构造变体）。
V10 新建 `Map16V10Inner(Map16Environment)`，按 `environment_seed` 传入四组实例参数：

| seed | label | 起点 a/b | 终点 a/b |
|---:|---|---|---|
| 0 | base | A / B | B / A |
| 1 | siding_goal | A / B | D / A |
| 2 | short_start | X / Y | B / A |
| 3 | cross_start | A / Y | D / A |

四例都保留核心机制：单线区段预约、节点容量 1、侧线 D 让行、`move_train` 整帧提交、
无安全完成路径即死锁。差异在会车点与最短 makespan。

`Map16V10Environment(V10Map, V4MapAdapter)` 只替换适配器的 `_inner`：

- 公开面：`scenario_descriptor()` 输出 label/起点/终点/侧线，`_public()` 增加 `goal`、
  `ticks_remaining`、`siding_nodes`；这些本来就在 Observation 里可见，不属于新增泄漏；
- 密封面：`sealed_truth()` 只多出 `shortest_makespan`（最短排程），只在 hash 与 judge 中；
- judge：增加 `environment_seed`、`invalid_count`、`used_siding`、`sidings`、`shortest_makespan`；
- 指标（6 条）：`mission_success`（主）、`legal_action_rate`、`node_capacity_conflicts`、
  `deadlock_count`、`makespan_gap`、`committed_ticks`；
- `mechanism_triggered()`：至少提交过一次移动且列车进过侧线。

`rule_hash` = 本模块 sha256 + `RULE_SOURCES`（V4 `map16.py` 文件内容），因此 V4 规则变化会被哈希捕获；
本次未改 V4 文件，冻结校验仍 9/9 `unchanged`。

## 3. 证据

- 离线：`seed_effective=True`、4 个不同 `scenario_hash`；Oracle 4/4（机制触发 4/4、动作数 20/14/16/12
  均在预算 30 内）、公开启发式 4/4、三消融（`no_siding` / `route_only` / `double_booking`）0/4、
  `legal_random` 0/80；
- 独立核对：30 图 × 144 seed 实例 0 违规、回放确定 30/30、seed 互异 30/30；
- 公式级复算：新增 `_f16`（`status` 判成功），30/30 图、1093 次检查 0 不一致；
- 真实 MiMo（阶段 12，`ledger_v10_018.jsonl`）：3 局、非法动作 0/0/0，成功 1/3（seed 1，19 决策），
  seed 0/2 在 7/4 决策后 `NODE_CAPACITY_CONFLICT`；结算 CNY `0.01593856`，无未知消费。

## 4. 边界

- 只改实例参数，不改 V4 规则、动作契约、成功条件；历史 MiMo 局（无 MAP-16 局）不受影响，
  但 MAP-16 的 `rule_hash` 与 `scenario_hash` 是新值，不能与 V8 适配器值直接对齐；
- 4 个实例只改起点/终点，节点容量与侧线固定（1 / {D}）；MiMo 仅 3 局，不能据此判断能力上限；
- V6 的 `map16_l1/l2` 场景仍按难度变体处理，不作为 seed。

## 5. 回滚

删除 `v10/runtime/map16.py` 并把它从 `runtime/catalog.py` 的 `V10_MAPS` 移除，即可回到 V8 适配器回退；
`map16` 的 baselines、测试与 `_f16` 一并移除。
