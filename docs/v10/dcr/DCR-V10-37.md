# DCR-V10-37：冻结校验按 LF 归一 + 本地数据测试跳过（让 CI 可复现）

- 状态：`accepted_by_agent`（`agent_reviewed`）
- 类型：**工程可复现性**（不改规则、不改指标、不改任何 V8/V9 冻结文件）
- 关联：`freeze-manifest.json`、`DCR-V10-36`
- 代码：`v10/freeze.py`、`tests/test_v9_audit.py`、`tests/test_v9_metric_checks.py`

## 1. 问题

CI 在 V10 收尾期间连续失败，暴露两个与内容无关的可复现性问题：

1. **冻结清单哈希的是工作树原始字节**：本机工作树是 CRLF，干净 checkout/CI 是 LF，
   同一份内容得到不同 sha256，`freeze verify` 与 `test_tracked_v8_v9_files_are_unchanged`
   在 CI 必然判为漂移。
2. **4 个 V9 回归测试读取 `runs/v8`、`runs/v9`**：`runs/` 按项目约定不纳入 Git，
   CI 没有这些本地生成物，测试以 `FileNotFoundError` 失败。
3. **测试导入 `scripts.run_*.py`**：CI 用 `uv run pytest`（console script）时仓库根不在
   `sys.path`，`tests/test_v5_pilot_controls.py` 收集失败；本地惯用 `python -m pytest`
   会把 CWD 放进 `sys.path`，因此长期掩盖了这个问题。

## 2. 处理

- `freeze._sha()` 先做 `\r\n → \n` 归一，再计算 sha256；用 `freeze write` 重新生成清单。
  **所有 V8/V9 源文件未被修改**（`git status` 对这些路径为空），清单变化只是哈希口径变化。
- `tests/test_v9_audit.py` 与 `tests/test_v9_metric_checks.py` 增加模块级 `skipif`：
  `runs/v8/results_90.csv` 不存在时跳过，并写明“runs/ 为本地生成物”。
- `pyproject.toml` 的 `[tool.pytest.ini_options]` 增加 `pythonpath = ["."]`，
  让 `python -m pytest` 与 `uv run pytest` 都能导入 `scripts/`。

## 3. 验证

- 本机：`freeze verify` 9/9 `unchanged`；13 个相关测试通过。
- 干净 worktree（等同于 CI checkout，LF）：`freeze verify` 9/9 `unchanged`（runs 两项 `absent`），
  console-script `pytest` 全绿（1141 passed、10 skipped，4 个 V9 测试按预期 skip）。
- 包级 lint 仍为全仓 `ruff check .`（仅排除 `worlds/v4/**/planning` 的手写审计脚本）。

## 4. 边界

- 归一化意味着“仅换行变化”不再触发冻结告警；这是有意的：换行不是规则变化，
  且不同平台的 checkout 会产生不同换行。真实内容变化仍会被 sha256 捕获。
- 历史 V8/V9 局仍只在本机可复算；CI 只验证“文件未变”，不重放本地 Trace。

## 5. 回滚

恢复 `_sha` 的原始字节哈希并重新生成清单即可；测试的 `skipif` 可单独移除。
