# DCR-V12-01：`facts` 动作字段的公开契约无法表达内部字段名

- **状态**：`agent_reviewed`（未 `human_approved`）
- **严重度**：高（影响 MAP-22 的记忆通道与 `route_recall` / `mechanism_triggered`）
- **发现于**：V12 主矩阵 54 局真实执行（MiMo，`lab-20261025T120807Z-3aaedd0f`）
- **类别**：接口假象（contract artifact），**不是**模型能力差异
- **影响范围**：MAP-03、MAP-22（实例契约里含 `facts` 字段的图）

## 1. 观察事实

MAP-22 九局里 `write_memory` 共被调用 **182 次**，其中 **175 次被环境拒绝**为
`INVALID_MEMORY_PAYLOAD`（96.2%）：

| 实验臂 | 调用 | 被拒 | 写入成功 |
|---|---:|---:|---:|
| `basic.v1` | 100 | 96 | 4 |
| `memory.v1` | 73 | 72 | 1 |
| `planning.v1` | 9 | 7 | 2 |

模型实际写出的内容（原文摘录，均被拒）：

```json
[{"at_sign": "leaning_3"}, {"came_from": "pale_7"}, {"path_to_here": "pale_7->south->leaning_3"}]
[{"path_history": "camp->split_1->hollow_2->scorched_6->hollow_2->split_1"}, {"split_1_bearings": "east,south"}]
[{"route_from_camp": "camp->west->split_1->south->hollow_2"}, {"return_path": "hollow_2->north->split_1->east->camp"}]
```

而环境要求的是：

```json
[{"key": "bearing", "value": "west"}]
```

## 2. 根因

公开契约由 `v10/contract.py::render_annotation` 从 `V8Action` 注解渲染。
`facts: list[dict[str, Any]]` 渲染成：

```
- write_memory: {"tool": "write_memory", "facts": [{"<key>": <value>}]}
```

`<key>` / `<value>` 是**占位符**（`_key_label` 把标量键统一写成 `<key>`），
它只说明"这里是一个字典"，**没有说明字典里必须恰好有 `key` 和 `value` 两个字段**。
模型于是把 `{字段名: 值}` 理解为"任意键值对"，写出了语义正确但结构不合规的内容。

MAP-22 的公开规则写的是"把 1–3 条 `{key,value}` 写进 `agent_notes`"——文字里确实有
`key`/`value`，但同一份 prompt 里的**结构化契约**与之冲突（占位符版本更像"任意键"），
模型选择了后者。

这与 V10 已记录的 DCR-V10-24（契约只列字段名不列类型）、DCR-V10-25（取值结构未公开）
属于同一类缺陷：**契约渲染无法表达嵌套结构约束**。

## 3. 后果（对 V12 结论的影响）

1. MAP-22 的 `map22.v10.route_recall` 在 9/9 局都是 `NOT_APPLICABLE`，理由显示
   "未写记忆"——但模型**写了**记忆，只是键名不合规。这个标签是**事实错误**。
2. `map22.v10.mechanism_triggered` 在 9/9 局为 `False`，包括 2 局成功——机制指标
   出现假阴性。
3. 因此 **MAP-22 的"记忆是否减少迷路"这个研究问题在本轮无法回答**：
   被操纵的变量（记忆）实际上被接口切断了。

`mission_success` 仍然可用（它来自环境终局，不依赖记忆键名），但单看它不能回答
记忆假设。

## 4. 处理（已执行）

**不修改 V10/V11**：冻结运行时、指标公式、历史 trace 与账本一律不动。

在 V12 的 Lab 运行链路里新增一个**版本化契约补丁**
（`src/agent_arena/lab/contract_v12.py`，版本 `v12-contract-1`）：

- 只对**实例契约里真的含 `facts`** 的图追加一条公开说明：
  `facts 的每一项必须是恰好两个字符串字段的对象：{"key": "<str>", "value": "<str>"}`；
- 补丁写入 `result.provenance.contract_augmentation`（版本 + 命中说明）；
- 补丁改变 `prompt_hash`，因此**跨版本局不配对**；
- 环境校验不变：错误形状仍被拒（`tests/test_v12_contract_patch.py` 覆盖）。

随后以**补充实验**重跑 MAP-22 九局，作为"接口修复后"的独立版本。
