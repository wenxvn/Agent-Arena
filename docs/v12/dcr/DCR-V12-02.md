# DCR-V12-02：`route_recall` 的观测口径要求"方位序列"，但公开信息未表达这一点

- **状态**：`agent_reviewed`
- **严重度**：中（影响 MAP-22 的记忆质量指标，不影响 `mission_success`）
- **发现于**：DCR-V12-01 修复后的版本复跑（`lab-20261025T134724Z-fa696780`）
- **类别**：指标可观测性 / 公开信息不足
- **上游**：DCR-V12-01（`facts` 契约）

## 1. 事实

DCR-V12-01 修复后，`write_memory` 的拒绝率从 **96.2%（175/182）降到 0%（0/15）**，
但 `map22.v10.route_recall` 在 9/9 局仍然是 `NOT_APPLICABLE`。

原因是两条**不同的**约束：

| 层 | 要求 | 状态 |
|---|---|---|
| 契约层 | `facts` 每一项必须是 `{"key": str, "value": str}` | 已由 `v12-contract-1` 补清楚，通过率 100% |
| 指标层 | `key` 必须取 `bearing` 或 `path_state`，值必须是**方位序列** | 公开信息里没有表达 |

环境实现（`v10/runtime/map22.py::_written_route`）：

```python
for note in self.notes:
    if note["key"] == "bearing":
        route.append(note["value"])
    elif note["key"] == "path_state":
        route = [item for item in note["value"].split(",") if item]
```

模型修复后写出的内容（结构合规、语义合理，但键名不在口径内）：

```json
[{"key": "at_sign", "value": "leaning_3"}]
[{"key": "came_from", "value": "pale_7"}]
[{"key": "path_to_here", "value": "pale_7->south->leaning_3"}]
[{"key": "split_1_bearings", "value": "east,south,west"}]
```

MAP-22 的公开规则原文是：

> `write_memory(facts)` 把 1–3 条 `{key,value}` 写进 `agent_notes`；内容原样保留，
> 是跨阶段唯一可靠通道。

它只说了"任意键值对会被保留"，**没有说**哪个键会被指标读取。于是：
模型的行为是合理的（自证记忆），但**指标读不到**，`route_recall` 变成 `NOT_APPLICABLE`。

## 2. 为什么这是问题

`route_recall` 是 MAP-22 的 **secondary** 指标，也是 V10 DCR-V10-12 专门为
"记忆是否真的被用于返程"设计的。现在它：

- 在**未写记忆**时是 `NOT_APPLICABLE`（设计如此，正确）；
- 在**写了合规记忆但键名不同**时**也**是 `NOT_APPLICABLE`（这是口径问题）。

两者混在同一个状态里，读报告的人无法区分"没记"和"记了但读不到"。
本轮 9 局里，`memory.v1` 只写了 0–2 次，`basic.v1` 写了 2–4 次，全部落在第二类。

## 3. 处理

**本轮不改 V10 指标，也不改公开规则**（会改变 `rule_hash` 与历史可比性）。改为：

1. 诊断层新增 `memory_key_not_in_metric`（MAP-22 专属）：当 `write_memory` 全部成功、
   但没有任何 `bearing` / `path_state` 键时，输出一条 warning，明确写"记忆已写入，
   但键名不在指标口径内，`route_recall` 因此为 N/A"，并给出证据步；
2. 报告与 UI 保留 `NOT_APPLICABLE` 原状态（不伪造数值），但附上这条诊断；
3. 结论层明确写：**MAP-22 的"记忆是否减少迷路"在本轮仍不可回答**——不是模型没记，
   而是指标口径与公开信息之间还有一层未对齐。

## 4. 建议（V13 决策，本轮不执行）

- 在 MAP-22 公开规则里显式写"若要指标可读，用 `key=bearing`（单个方位）或
  `key=path_state`（逗号分隔的方位序列）"；
- 或者把 `route_recall` 改为读取"任何能被解析为方位序列的值"，并在指标卡里声明
  新的匹配规则；
- 两条路都必须新增版本命名空间，不能覆盖 V10 的历史值。
