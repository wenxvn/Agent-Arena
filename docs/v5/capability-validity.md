# V5 Pilot 的能力效度边界

## 可支持的解释

- **MAP-08**：seed 0/4/8 分别覆盖 B/D/F 漏点，可描述首次测试选择、公开签名后的假设更新、测试数量、错修和结束时压力。只有一个 seed 对应每个故障点；这不是随机总体样本。
- **MAP-16**：ReAct 与公开约束表按同一 scene label 配对，可描述预约冲突、死锁、makespan 和相对 BFS 最优差距。三 seed 是同一个小拓扑的重复执行。
- **MAP-18**：告警开/关使用同一状态和 seed，可描述恢复调度与乘客账本是否因公开非定位预警改变。三 seed 标签不创建新随机扰动。
- **MAP-22**：所有对照从同一合法探索前缀的 L/tick 12 开始，故对照聚焦返程阶段的 agent memory 使用。它不能衡量从未知起点开始的探索策略或探索效率。
- **MAP-26**：free diagnosis 的三个 seed 覆盖三类故障；三个恢复条件都从同一合法错误替换反馈状态分叉。隐藏反馈是信息剥夺，不是等信息基线；每个恢复条件仅一个 episode。
- **MAP-30**：完整历史、最近 5 步、最近 5 步加结构化案卷三条件从同一调查 prefix 进入长间隔证据回忆和证据链提交；比较仅限已公开证据、Q4 召回、案卷使用和指控谨慎性。seed 0/1/2 为同一案情重复。

## 不支持的结论

- Oracle 回放与离线求解只证明运行规则下存在可行路线和局部数学核验，不证明模型能力。
- 六局 smoke 检查接口、trace、usage 和计费闭环。成功或失败均不得替代完整矩阵条件对照。
- 这 39 局不构成模型排名、通用规划能力、跨地图迁移或部署可靠性证据。
- 单局被 100 决策、12 分钟或全局 240 分钟上限截断时，必须标成删失或运行预算停止；不得写成最终能力失败。
- Provider 错误、unknown spend、缺失 usage 和本地验证失败是运行证据，不归因给 Agent 行为。
- 对固定 scene 的重复 seed 不报告独立样本置信区间。报告精确计数、逐 seed 配对差和条件边界，避免虚假独立性。

## 主要混淆因素

模型输出本身可非确定；系统提示、JSON object transport、决策预算和最近五条历史是固定实现条件；MAP-16/18/22/30 没有随机环境变体；MAP-22/30 的共享前缀控制了历史但缩小了行为范围；MAP-26 feedback 轨道单条件只有一例。新一轮研究应先扩展合法场景和更多独立实例，再讨论推断区间。
