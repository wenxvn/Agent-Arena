# V7 设计变更请求（人工已复核；规则变更未批准）

> 状态：12 条均已由人工复核登记，但仍保持 `proposed`。V7 **没有**修改任何 V4/V5/V6 规则、Oracle、账本或注册表。每条 DCR 的规则变更仍需在对应地图运行时接入前单独决定；批准后必须以新规则版本 + 回归测试落地。
> `V7-DCR-*` 与 V6 `DCR-001..010` 不混用。未决 DCR 不阻塞 30 张设计卡和六图离线层，但阻塞对应地图的运行时接入与真实实验。

## V7-DCR-001：MAP-01 的舰桥确认动作与断供计数观测

- **证据**：`worlds/v4/MAP-01/map_spec.yaml` 的 `terminal_success` 含 `bridge_confirmation == complete`，但 `actions` 只有通用 `interact`；`oxygen_off_ticks` 只在私有/内部计数，未列入 `public_observation_fields`。
- **影响**：V7 无法仅凭公开 Observation 判定“确认”语义；无法区分“断供 3 tick 安全”与“4 tick 失败”的公开边界。
- **请求决定**：是新增明确的 `confirm_repair` 交互操作，还是把 `bridge_confirmation` 改为由既有 `interact(bridge_console, ...)` 的公开结果表达？是否公开 `oxygen_off_ticks` 或只公开“距上限剩余 tick”？
- **本轮处理**：设计卡写明两种候选语义；不实现运行时，不改规则。

## V7-DCR-002：MAP-02 双目标权重与“部分完成”记分

- **证据**：`terminal_success=[nav_core_secured, crew_in_E, tick_lte_20]`，没有目标权重；V7 提纲要求“双目标完成度=已达成目标权重的明细”。
- **影响**：若 V7 自行设权重，会把评分自由度偷偷写进测量。
- **请求决定**：确认权重是否固定（如 0.5/0.5）或只报 `(rescue_done, nav_secured)` 二元组，不合成。
- **本轮处理**：设计卡默认**不合成**，只报明细；若未来需要单值，必须先登记权重与敏感性。

## V7-DCR-003：MAP-03 记忆失败与资源失败的独立原因码

- **证据**：`terminal_failure` 只列 `SAMPLE_COLD_WINDOW_EXPIRED / EVA_OXYGEN_EXHAUSTED / ROUTE_KEY_REJECTED / RETURN_WINDOW_EXPIRED`；“保留码却漏阶段”与“阶段全过但码错”没有独立码。
- **影响**：V7 的“长延迟信息准确率”与“阶段完成覆盖率”无法在失败局上稳定归因。
- **请求决定**：新增只读原因码（如 `EARLY_FACT_NOT_SUBMITTED` / `WRONG_ROUTE_KEY` / `PHASE_SKIPPED`），或在 trace 中保留阶段位与提交内容的公开快照。
- **本轮处理**：设计卡用两条手算失败轨迹区分；不新增运行时码。

## V7-DCR-004：MAP-05 窗口可行性修订的引用

- **证据**：`worlds/v4/README.md` 记载 MAP-05 原始窗口不可行，已提交手算 DCR；`docs/v5/design-discrepancies.md` 也有历史修订。
- **影响**：若运行时沿用原始窗口，“三束信号全部可达”不成立，主指标无意义。
- **请求决定**：确认运行时引用哪一版窗口，并把窗口表哈希写入 scenario hash。
- **本轮处理**：设计卡只使用修订后可行情景；运行时接入前必须复核。

## V7-DCR-005：MAP-06/11/21 的信息呈现与“能力”边界

- **证据**：MAP-06 公开 `known_forecast_accuracy`；MAP-11 公开 `posterior_unstable_probability_belief`；MAP-21 公开 `posterior_over_eruption_ticks`。这些字段可能已经完成部分推断。
- **影响**：若地图直接给后验，“信息价值/风险决策”测到的是信息使用，不是推断；不能称“纯能力提升”。
- **请求决定**：确认这些字段是地图计算值还是 Agent 可写字段；若为地图计算值，V7 对照组标为“信息可用性实验”，并增加“无后验/仅有原始观测”的条件。
- **本轮处理**：设计卡按“信息使用”定义主指标，并标注条件类型。

## V7-DCR-006：MAP-07/09 的级联/传播 instrumentation

- **证据**：MAP-07 需要“净流量偏差积分”，MAP-09 需要“故障传播规模”，但公开字段只有水位/系统状态，没有事件级的“哪个子系统因何进入不安全态”。
- **影响**：只能从水位曲线近似，无法区分“同一故障的持续”与“二次传播”。
- **请求决定**：是否允许新增只读事件（不改规则）记录 `subsystem_entered_unsafe` 与因果父事件？
- **本轮处理**：设计卡给出仅用公开状态的保守公式；传播规模标为需要 instrumentation。

## V7-DCR-007：MAP-12 日结算顺序与动作上限

- **证据**：地图有每日 2 动作、供热/口粮双连续欠供、温室/科研周期；`map_spec` 未固定“日结算”与“动作效果提交”的先后。
- **影响**：长期库存与连续欠供天数对结算顺序敏感，指标可能被实现顺序改变。
- **请求决定**：冻结每日结算顺序（动作→资源→欠供判定→日推进）并加运行时回归测试。
- **本轮处理**：设计卡明确要求先固定顺序，再接入运行时。

## V7-DCR-008：MAP-15 的“未见状态预测”代理

- **证据**：动作只有 `inspect_symbols / record_rule / choose_door`，没有显式 `predict`；提纲要求“未见状态预测正确率”。
- **影响**：只能把“首次进入未见奇偶组合时的选择”当作预测代理，无法区分“预测对但执行错”。
- **请求决定**：是否新增非执行型 `record_prediction` 动作（不计 tick 或计 0 tick，judge-only 校验）？
- **本轮处理**：设计卡明确代理定义与局限，不伪造显式预测。

## V7-DCR-009：MAP-18 故障载荷与成功阈值

- **证据**：V6 离线验证报告指出，若列车在 tick 5 前已完成红线任务，闭塞不约束结果；成功阈值 13/18 允许取消两条红线任务。V6 0/10 仍主要是策略失败。
- **影响**：当前实例不能稳定测量“在线恢复调度”；0/10 不能证明能力为零。
- **请求决定**：是否登记新的强制窗口规则（例如红线任务必须在闭塞期间仍可恢复），或把 L1 无故障、L2 已知故障、L3 在线故障的成功阈值分开？
- **本轮处理**：设计卡要求先离线证明“故障实际约束最优策略”；不满足则标 `environment_unsolvable`/设计问题，不改规则。

## V7-DCR-010：MAP-19/20 的精确温度可见性

- **证据**：MAP-19/20 公开 `temperature_bands`，精确温度在私有字段；V7 提纲要求“温度超阈面积/最大节点越限量”。
- **影响**：用带下界会低估面积，用私有精确值又与“Agent 可见信息”不同；两者不能混报。
- **请求决定**：确认指标计算允许使用离线精确温度（裁判侧），并在报告中注明“裁判侧精确值”；Agent 决策仍只看带。
- **本轮处理**：设计卡明确两套口径，运行时 extractor 需声明使用哪一套。

## V7-DCR-011：MAP-22 的实例最优值与重复边定义

- **证据**：V6 已把 `optimal_moves` 按实例化（L1=4，L2=4/8，L3=8），但 V4 默认是 8；公开位置签名可能重名。
- **影响**：若沿用默认 8，短图会出现负 gap；若用无序边计重复，合法往返被误判为重复。
- **请求决定**：确认 V7 使用“按实例最优值 + 有向公开边”定义；是否允许在 trace 中增加公开节点别名（不泄露全图）？
- **本轮处理**：extractor 已按实例表和**有向**公开签名实现；卡片注明代理局限。

## V7-DCR-012：MAP-27 部分完成与成功谓词

- **证据**：`success_predicate` 与 `OBJECTIVES_INCOMPLETE_AT_BASE` 并存；中继/采样/救援可能部分完成。
- **影响**：“协同任务完成率”需要明确部分完成是否计入成功。

## 处理原则

1. 先人工决定 DCR，再改规则；V7 不自行批准。
2. 任何规则变更必须：新版本号 + 迁移说明 + 旧行为回归 + 新 Oracle + 无泄漏检查。
3. 历史 trace/账本不改写；新规则只影响新 episode。
4. 未决 DCR 不阻塞 30 张设计卡，但阻塞对应地图的运行时接入与真实实验。
