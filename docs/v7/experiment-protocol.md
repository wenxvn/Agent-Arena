# V7 评测与预注册协议

## 1. 默认状态：离线

V7 默认只做离线指标复算与设计审核。任何真实模型调用必须另行满足：

- 用户单独授权与预算登记；
- 固定 provider、模型、temperature、reasoning 设置；
- 冻结 scenario hash、prompt hash、runtime commit、离线门禁 hash；
- 不重开已关闭账本，不创建未登记预算。

本轮没有新增付费调用，也没有新建账本。

## 2. 样本单位

| 单位 | 定义 | 不可混淆 |
|---|---|---|
| world | 十种风格 | 不是统计样本 |
| map | 30 张独立关卡 | 不是同一量表的 30 个刻度 |
| instance | 同一地图的不同结构实例 | 固定 scene 的 seed 不是新实例 |
| condition | 预登记对照（记忆/反馈/告警/信息量） | 条件差异不等于能力差异 |
| run | 一次 episode | |
| seed | 模型采样或场景随机标签 | 固定 scene 多 seed 只是重复采样 |
| agent/model | 被测系统 | 单模型结果不能外推跨模型 |

## 3. 每图预注册字段

每张卡在测试前冻结：

1. 主指标（1–2 条）、方向、单位、分母、窗口、缺失规则；
2. 硬约束与安全指标；
3. 主要对照与配对方式；
4. 动作/决策预算、tick 预算、费用预算；
5. 停止规则（最大局数、最大费用、连续 provider 错误、schema 失败阈值）；
6. 预计样本量与 seed 策略；
7. 失败归因码表；
8. 可解性证据（Oracle/独立求解器/下界）。

未登记的事后分析标为 `exploratory`，不得写成主结论。

## 4. 配对与对照

- **同实例配对**是主要因果对照：同初态、同公开 Observation、同预算、同 Action contract，只改预登记机制。
- 多 seed 只报告重复运行稳定性；不能把 3 个采样 seed 当成 3 个独立场景。
- 信息量不同的对照（公开表 vs 自行推断、可观测 vs 不可观测、full vs hidden feedback）标为**信息可用性实验**，不得称“纯能力提升”。
- 单列车 L1、无故障 L1、纯召回变体等降载实例必须与完整实例**分报**。

## 4.1 基线定义（Batch 8）

基线只用于回答“这个指标是否还有区分度”，不把基线的原始分数当成地图总分。

| 基线 | 定义 | 公平边界 | 当前状态 |
|---|---|---|---|
| Oracle / 独立求解器 | 在冻结规则上构造可行解；有最优证明才写最优，否则只写构造解 | 只用于可解性与上界参考，不作为 Agent 能力证据 | 六图有 V6 求解器，可离线重放 |
| 合法随机策略 | 只从当前 Observation 的合法动作中采样，固定 seed 与预算 | 不得读取隐藏真值、未来事件或最优路线；用于暴露“接口熟悉度”下限 | 协议已定义，V7 未实现运行器 |
| 规则启发式 | 地图专属的确定性脚本，只读公开字段 | 必须与模型使用同一 Action contract、同一预算；不得调用 Oracle 内部状态 | 仅以 V6 求解器动作作可行性参考，不冒充模型基线 |
| 机制消融 | 同模型、同 prompt、同预算，只移除一个预登记机制（记忆/诊断/规划/反馈） | 条件 ID 与公开信息必须可核对；信息量变化单独标为信息可用性实验 | 六图已有 V6 条件/trace，V7 只做离线复算 |
| 无记忆/无诊断/无规划 | 消融的特例，不是“更笨的模型” | 不得用赠送资源、延长步数或隐藏提示来补偿 | 按图在预注册中逐条登记，未登记标 exploratory |

报告基线时必须同时给出实例、条件、预算、有效分母和缺失/截尾状态；不同地图的原始成本不能相加，
也不能用“Oracle 成功”替代 Agent 成功。

## 5. 统计与不确定性

- 报告逐图逐实例原始值、有效分母、N/A、截尾、paired difference。
- 单次运行只作描述性统计，不做显著性、排名或跨模型结论。
- 有多个独立实例后，可按实例聚合并报告不确定性；模型随机性与实例随机性分开。
- 不把不同地图的原始成本相加；默认不发布 30 图单一总分。
- 若未来必须总分：先冻结标准化、权重、缺失值、安全惩罚，再做敏感性分析并展示分项。

## 6. 停止规则

立即暂停并记录阻塞，若出现：

- 硬约束冲突或规则不可解；
- 隐藏信息/未来事件/最优路线泄漏；
- 旧 V4/V5/V6 行为回归；
- 指标无法由日志计算却仍被报告；
- provider 连续错误、未知计费或预算超限；
- schema 失败达到预登记阈值（V6 为连续 3 次）。

## 7. 失败归因与报告

统一原因码见 `measurement-principles.md` §7。报告至少包含：

- 结果分布（success/failure/censored/invalid）；
- 每图主指标与安全指标；
- 失败原因码分布与代表事件序列；
- 资源/温度/水位/客流曲线；
- 成本（token、请求数、墙钟、费用、currency）；
- 与 Oracle/启发式/消融的对照；
- 数据泄漏检查结论；
- “设计态 / 运行时 / 真实模型”三分区。

## 8. 可视化

- 30×（结果、主指标、风险）矩阵；
- 每世界三难度分面；
- 同实例配对斜率图；
- 失败类型分布；
- 资源/温度/水位/客流时间曲线。

不要只画一个“30 图综合雷达”就宣称科学测量。

## 9. 历史与账本

- 不覆盖 V2/V4/V5/V6 的 Oracle、设计文档、账本、注册表、原始 trace。
- 不重新登记已关闭账本；不创建 BUDGET-04。
- 每批记录实际命令、真实输出、未解决问题、DCR 与下一批准入。
- 人工审阅字段保持 `pending_human_review`，执行模型不代签。
