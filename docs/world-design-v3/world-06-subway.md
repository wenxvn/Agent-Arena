# 06 废弃地铁：离散事件列车调度

## 机制图

检查公开轨道/占用/信号 → 配置道岔与授权信号 → 对单列车下达一步 advance → 占用目标区段并释放旧区段 → 核对终点、优先级和时限。

玩家始终在控制室；轨道网络与玩家房间分离。车辆只在 Agent 下令时前进；`wait` 不自动运行列车。共享区段互斥，列车进入干线后锁定已预留出口。

| ID | 关卡 | 设计与参考策略 | 主要边界 |
|---|---|---|---|
| SU-E | 最后一班车 | 把 switch 设 NORTH、信号置 GREEN，再令 train 1 连续前进两段到 north platform。 | 红灯不发车；一次 advance 只走一个区段；错岔路可恢复。 |
| SU-M | 会车与道岔 | 先让 A 完整离开 single_track 到 platform A，再切 B 路由放行 B。 | 共享单线同一时刻至多一车；冲突拒绝且不改变车辆位置。 |
| SU-H | 三车共享干线 | 18 tick 内依次调度 A、C、B；B 车进入 shared_track 后触发维护锁，可继续驶到 platform_b，之后需显式 release 才能更改总道岔。 | 初始维护锁为关闭；占用、入线后路由锁、A 先于 C 和时限均公开。Oracle 让 B 最后出发，能在 B 到站时完成目标；B 提前出发会增加可见解锁动作。 |

SU-H 原草案的“要求 A 先于 B 或 C”与参考序列 A-C-B 不一致；已规范为“救护车 A 必须先于 C 到站”，B 的维护锁只产生可见额外操作，不隐含改写优先级。设计依据：研究提纲 §7。
