# MAP-13｜四神之门

状态：`DESIGN_COMPLETE_PENDING_RUNTIME`。这是一个带空间标号语义的约束满足关卡：外侧四室在移动图上只与中央 C 相连，但符号谜题使用另一条明确标出的阅读序。破解者必须分别保留“房间连通图”和“碑文位置序列”，不可把逻辑相邻误当作房间之间有通道。

## 房间与两种关系

移动拓扑是固定星形：C 分别连 N、E、S、W，四个外室之间没有直接移动边。四符号 `日、眼、芦、甲` 各放入一间外室，每间恰好一个。

中央门楣的方向钉说明阅读序为 `N → E → S → W`，从 C 俯视按顺时针编号为槽位1至4。“两端”指槽位1和4；“右侧”指此序列中编号更大的槽；“相邻”指槽位编号差1，不表示星形拓扑中的通道相邻。这条方向钉是第五条消歧信息：若删除它，镜像读序 `N → W → S → E` 也各自得到唯一排列，符号会落入不同物理房间。

四间房各有且只有一条位置约束：

| 房间 | 碑文 | 在固定阅读序中的约束 |
|---|---|---|
| N | 日神不得居于两端 | `pos(日) ∈ {2,3}` |
| E | 眼神位于芦神右侧 | `pos(眼) > pos(芦)` |
| S | 甲神须与日神相邻 | `abs(pos(甲)-pos(日)) = 1` |
| W | 芦神不得居于首槽 | `pos(芦) ≠ 1` |

答案不是观察中可见的真相字段。阅读动作只公开对应碑文；方向钉也须在 C 亲自读取。最终物理答案由方向序和四条碑文唯一推出：按 `N,E,S,W` 顺序，符号为 `甲,日,芦,眼`，即 `N=甲, E=日, S=芦, W=眼`。

## 逐线索唯一性

`planning/constraint_audit.py` 对四符号的24种排列逐一检查。按 N、E、S、W 收集房间约束后，候选数为 `24 → 12 → 6 → 4 → 1`。唯一排列为 `甲,日,芦,眼`。分别删除 N、E、S、W 任一房间约束时，剩余解数为 `2、5、2、4`，所以四条房间碑文各自必要。删除方向钉时，两种读序给出的房间布局分别为：

- 顺时针：`N=甲, E=日, S=芦, W=眼`。
- 反向镜像：`N=甲, W=日, S=芦, E=眼`。

两者均符合其各自的“右侧/端点/相邻”解释；方向钉因此必要于确定实体房间映射。这里没有再叠加一条冗余的第五个位置谓词。全24排列枚举和必要性计数可由脚本重现，输出保存在 `planning/constraint_audit.json`。

## 动作节奏与成功策略

每条移动边耗1 tick；读碑、记录已见约束、设置完整试排和验证各耗1 tick。记录板只能在 C 使用，且只能记录已读碑文；它不替破解者推理。`set_trial_layout` 设置四室各一符号但不消耗验证次数；`verify_layout` 才是一轮开门尝试。错排次数达到3时终止，前两次错排后不会给出象限提示或哪条线索冲突。

手工路径保留两种解法过程：

1. **约束传播路线**：读方向钉并立即记录；依序访问 N/E/S/W，每读完一块就回 C 记录，利用候选集 `24→12→6→4→1` 推进；设置唯一排布并验证。成功 tick20，五条信息均先记录。
2. **系统枚举路线**：读方向钉后按 W/S/E/N 探索；回 C 后一次性登记方向与四条碑文，枚举24种排列；再设置并验证同一排布。成功 tick20，访问次序与中途记录策略不同。

两条路线都要亲自读取全部信息才有完整证据；评分看开门正确性、错误尝试数、验证前记录覆盖率及 tick，不把“看过”和“登记证据”混为一项。

## 手写失败与边界

`failure_traces/cases.yaml` 给出三个不同的证据错误：忽略方向钉而试镜像、漏用 E 室“眼在芦右侧”、漏读 W 室“芦不在首位”。每例均列三套不同试排和逐次验证；第1、2次错排仍可继续，第3次才终止。验证器只返回门未开与剩余容错次数，不反馈目标房间或正确符号。

必须手工验收：24种合法排列里只有一个过门；符号重复或遗漏不能形成完整试排；方向钉读序反转后房间映射镜像；错排2次后正确答案仍能开门；第三次错误立即失败；已读但未记录的碑文不计入证据使用率；固定 seed0 重置后，同动作序列的每个 tick 与终止状态一致。
