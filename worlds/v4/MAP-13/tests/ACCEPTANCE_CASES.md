# MAP-13 环境实现后验收用例

以下是实现阶段规则用例清单；当前只运行过独立的24排列设计审计和手写成功轨迹重放，没有运行 pytest。

1. Reset：seed0、位置C、移动边仅 C_N/C_E/C_S/C_W；四符号各用一次，目标映射保持裁判侧私有。
2. 四外室按 N-E-S-W 顺时针编槽位1–4；C方向钉只在 `read_inscription(C)` 后公开；方位解释必须与移动图分开。
3. N碑只说“日不在两端”；E碑只说“眼在芦右侧”；S碑只说“甲与日相邻”；W碑只说“芦不在第一位”。未读碑文不得出现在Observation。
4. 完整枚举24排列，唯一布局为 N=甲/E=日/S=芦/W=眼；按N→E→S→W依序施加四条约束时候选数是24/12/6/4/1。
5. 逐条删除房间约束，剩余满足排列数依次为2/5/2/4；删除方向钉时，CW与反向读序各自唯一但房间映射互为镜像。
6. 从外室只能沿本室到C的唯一星形边移动；输入边端点或当前起点不匹配时拒绝，不能外室间直达。
7. 碑文只能在当前房间读；约束只可在C登记且需此前读过；阅读与登记分别更新观察/证据状态。
8. 完整试排恰有N/E/S/W四室和日/眼/芦/甲各一个；重复、遗漏、额外符号在验证前拒绝，不扣tick或错误尝试数。
9. `set_trial_layout` 消耗1 tick但不计错误；`verify_layout` 消耗1 tick。前两次错误后episode仍运行；第三次错误后同tick以 `INCORRECT_ATTEMPT_LIMIT` 终止。
10. 两成功Oracle `constraint_propagation` 和 `systematic_enumeration` 各20 tick、记录5条信息、0次错排并开门；二者的访问/登记顺序须逐步一致。
11. F01首个试排是反向读序镜像布局；F02的三份试排分别只违反E约束；F03的三份试排分别只违反W约束。三案例第三次错误验证终止，失败反馈不带符号提示。
12. 正确布局验证立即终止成功；在2次错排后仍可正确提交并成功。
13. 同seed和动作重复reset-replay应生成相同tick、位置、已读/登记碑文、试排、失败计数、终止结果与状态hash。
