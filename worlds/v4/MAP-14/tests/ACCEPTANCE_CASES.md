# MAP-14 环境实现后验收用例

以下用例待 Phase 1 环境实现后执行；当前仅有独立审计脚本与纸面回放。

1. Reset：seed0、P位置、三锁型候选、三祭司公开身份/每人两条固定命题；实际B锁与乙真话身份私有。
2. 图边只有 P_A/A_O/O_J；P-J关闭，验证前后都不能直接移动。
3. 命题文字固定公开，`true_for_configs`裁判数据不公开；A档案未读取前Observation不包含其内容。
4. 对每一候选锁型和发言者，问句真值由固定配置谓词决定；唯一诚实者原样回答，两个说谎者反转；同动作同seed重置回答不变。
5. 每人恰有两条命题；每个claim_id最多询问一次，整局最多4条；第5问或重复问拒绝且不推进tick/预算。
6. 三锁×三真话者共9态，对固定问序A1/A2/B1/B2的四位答案码必须一一对应；验证 `truth_table_audit.json`。
7. 读档案只排除C，候选缩至6；A1/B1/B2答案是yes/yes/no时唯一为B/乙。
8. 自适应树每条分支最多4问且9个叶各出现恰好一次；seed0走A1 yes、A2 no、B1 yes后落在B/乙。
9. `compare_evidence`仅位于O，只可引用已读档案/已获答案ID；回执不得表示候选正确或泄漏剩余数量。
10. 首次错配置提交继续episode；正确配置可在一次错交后打开；第二次错误提交同tick终止。
11. 锁型正确但真话者比较猜测错误时，门按锁型开启，辅助识别分数为错；不修改提纲的通关谓词。
12. 两成功Oracle：档案路线11 tick/3问，adaptive路线8 tick/3问；位置、答案、证据、提交应逐步一致。
13. F01/F02/F03固定答案与提问序分别落到两次错交；F03问句子集需保留A/甲与B/乙两个兼容候选。
