# MAP-17｜早高峰

状态：`DESIGN_IN_PROGRESS`。本关单独设计为时刻表优化题：环线A-B-C-D-A挂接B-E-F支线，瓶颈固定在双向共用的B-C单段；四班车分别从A/C/D/F发车，面对5组固定OD客流。核心不是“尽量多跑”，而是在同一张客流表上公开比较准点、服务率、乘客等待和能耗之间的取舍。

## 人工固定的客流与车队

网络每段单程行驶恰好1 tick，线路无随机延误。四站环线边为AB、BC、CD、DA，支线为BE、EF；B-C是唯一物理区段，双向合并容量1，即同一tick最多一列车通过。各站可停放至多2列车，所有列车座位容量3。

初态4列车为 `T_A@A`、`T_C@C`、`T_D@D`、`T_F@F`。tick0一次性到齐10名乘客：A→C 2人、B→E 2人、C→F 2人、D→B 2人、F→A 2人。客流矩阵、列车位置、座位与站台容量均公开；seed0没有隐藏需求或随机变化。时间窗固定为tick0至tick11共12个结算tick；能耗上限18。

每个tick提交一次全局时刻表行，四列车同时执行各自的一个操作；未列出的车保持在站。`release(next_station)`驶过一个相邻区段，耗1能量并占用该段本tick；抵站时自动卸下目的地到达的乘客。`stop(boarding_manifest)`原地停1 tick、不耗能，按提交的乘客清单装载。`switch_line(branch|ring, boarding_manifest)`只允许在B执行，作为1 tick站停，可同时装卸乘客、提交登车清单，并设定离站支线/环线；本身不耗能。`delay`原地等1 tick，不装卸、不耗能。B站乘客换乘不同列车须完整等待1 tick，该tick照常计入乘客等待、不额外扣能；本图两条参照时刻表均不使用乘客换乘。

事件顺序固定：先验证当tick操作、下一相邻站、B-C区段预约、站台终态容量、登车清单合法性与剩余能量；若冲突则当tick整批失败且位置/能耗/tick不变。通过预检后，对tick开始仍在站台的未上车乘客各累加1乘客等待单位；所有区段移动同步执行，再在抵站自动卸客；`stop`/`switch_line`按本tick清单装客；最后tick推进。未在tick12前送达的人计为未服务并累计至12 tick。服务率按“在目的站实际下车人数 / 10”计算，不按上车数计算。

## 两个手工Pareto参照策略

两份12行时刻表在 `planning/hand_traces.json` 中逐tick手工编写，审计器只复核已写线路、同步占用和指标，不生成线路或策略。

| tick | 准点优先 `T_A / T_C / T_D / T_F` | 节点要点 |
|---:|---|---|
| 0 | stop / stop / stop / stop | 四车各接起点2人 |
| 1 | A→B / C→B / D→C / F→E | T_A与T_C同时占B站两泊位 |
| 2 | B→C / B换支线 / delay / E→B | T_A独占B-C；T_C接1名B→E，T_F补入B |
| 3 | hold / B→E / C→B / B→A | T_C、T_F离开B，T_D进入；B-C由T_D单独使用 |
| 4 | hold / E→F / B换支线 / hold | T_D接剩余1名B→E |
| 5 | hold / hold / B→E / hold | 最后一名B乘客抵达E；tick6前送完全部10人 |
| 6–11 | 全部hold | 维持12 tick统一评分窗 |

准点优先点为服务10/10、等待16人tick、能耗11、最后交付tick6。能耗优先表省略T_F班次，只服务A→C、C→F、D→B和B→E共8/10人；能耗8、等待38人tick、最后交付仍为tick6，F站两人留候至tick12。它恰好达到80%门槛，并以未服务客流换取3点能耗。两参照点互不支配：准点表服务更高且等待更少；节能表能耗更低。本图公开这两个“手工参考Pareto锚点”，不声称它们构成对所有可能时刻表的全局最优前沿。

辅助 `non_dominated_distance` 为候选指标到上述手工参照集合的最近归一化欧氏距离；维度和范围公开：`(1-service_rate, passenger_wait/120, energy/18, last_delivery_tick/12)`，各维等权，不汇总为隐藏通关分。原始四项指标始终单独报告。

## 失败、边界与防作弊

- F01让T_A于tick2走B→C，同时T_C走C→B，触发B-C共享瓶颈反向交换；整轮不动、不耗能、不推进tick。
- F02让B站已有T_A、T_C两车时仍令T_F从E驶入B，tick末将有3车，超出2泊位容量。
- F03只排T_C与T_D两班，送到6/10人，能耗仅6但低于80%服务阈值。
- B01重放节能表，恰为8/10服务且能耗8，验证80%门槛的包含端点。
