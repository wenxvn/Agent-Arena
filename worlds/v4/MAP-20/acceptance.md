# MAP-20 设计验收

状态：`DESIGN_COMPLETE_PENDING_RUNTIME`。本图的独立挑战是把有限的同tick来水分给三块不同热负荷的设备区；相邻支路可救急转供，但固定损失20%。规格、逐回合手写账、三种策略结果、失败原因和边界由 `planning/flow_audit.py` 专属回放器核对。当前没有环境回放、Agent运行或模型实验结果。

## 逐图设计核对

- [x] 固定S到A/B/C直供、A-B与B-C可双向旁路的水网；旁路用水必须来自当tick供给，不可制造水或串联转送同tick新收到的水。
- [x] 为避免“总水量约束冗余”及“旁路仅装饰”，三条上游直供支管各自最多2.5、S总量最多6、区阀A/B/C分别最多4/4/3；`map_spec.yaml` 的动作范围与流量范围一致。
- [x] 以十分之一单位整数刻度结算；旁路输入按0.5单位步长、单链上限2单位，精确扣除输入的1/5损耗，并逐帧验证水量守恒。
- [x] 明确满载/降载/停机各区热量与产能、初始温度7/6/5、严格高于10才过热、负温度截为0、同tick安全后才记产能、十tick至少15分成功。
- [x] 明确每tick一个温区精确读数、其他区仅温度带，以及源预算、支管/旁路/区阀原子校验；非法控制整帧拒绝且不改温度、不消耗时间。
- [x] 手写A区优先方案：先用B→A转水偿还A的初始热债，再统一降载，十tick产能56、水源用量52、旁路损失0.4、峰温9.4。
- [x] 手写动态轮换方案：按热余量让C/A/B依次满载并转水，十tick产能59、水源用量57、旁路损失0.8、峰温9.4；相对A优先方案增加3点产能但多耗5单位水。没有将任一手写表冒称为全局整数最优。
- [x] 手写十tick精确产能边界方案：三区降载三tick后全部停机，恰得15分且保持安全，验证成功条件为`>=15`。
- [x] F01展示按热负荷估水导致A过热；F02展示支管各自合法但源总量超限的整帧拒绝；F03展示把旁路误算无损最终使A达到10.6过热。
- [x] B01验证源预算正好6单位可接受；B02验证恰15分通过；B03验证C区收到3.2单位超过3单位阀容量且不部分结算。
- [x] 用水量守恒和末态热余量手算72分的线性能量松弛上界，并明确它忽略离散负荷、支管和损耗，仅为宽松上界；56/59分成功表证明15分目标可达。
- [x] 专属回放器逐步复核三份各10tick手写策略、三类失败、三个边界及温度带Observation；生成30行seed0公共Oracle并在两次连续运行中逐字节比对SHA-256。
