# MAP-20 运行时实现后验收用例

这些是后续实现的验收规格。本设计阶段只运行MAP20专属手工账本回放器，不运行pytest或环境代码。

1. Reset seed0时拓扑为S-A/B/C直供及A-B、B-C旁路；初始精确温度为`[70,60,50]`十分之一度，普通Observation只显示`[WARM,WARM,COOL]`。
2. 每tick最多读一个区。读数返回被选区当前精确温度与上一tick该区差分；未选区精确状态、未来温度、Oracle分配不得进入Observation。
3. `set_flow([A,B,C])`每支路范围0–25刻度、总和不超过60。每支路25刻度、总和75的帧必须以`SOURCE_BUDGET_EXCEEDED`失败；温度、产能与tick均不变。
4. 单一支路大于25刻度时以`FEEDER_CAPACITY_EXCEEDED`失败，即使源总和未超60也不得允许。
5. 旁路输入为0–20刻度、每5刻度一档；同链每tick最多一个方向。输入10刻度时受区恰收8刻度、总损失2刻度；输入非5刻度倍数、超量、反向双开或对端非法时整帧拒绝。
6. 旁路出水只能来自发送区本tick的直供量；同一份收到的旁路水不能在本tick继续转送，所有支路的发送合计也不能超过其直接来水。
7. 直供`[20,20,20]`加B→A输入10刻度，区收水必须为`[28,10,20]`，损失为2刻度，总交付量为58刻度且守恒；A-B和B-C同时向同一方向转水时同样逐刻度守恒。
8. 区阀接收上限分别为40/40/30刻度。直供`[20,20,20]`与B→C输入15刻度导致C收水32刻度，应以`ZONE_VALVE_CAPACITY`拒绝，不得部分结算。
9. 区热更新按同tick选择的负荷档及实际收到水量，同时计算三区`max(0,T+heat−water)`。结果严格高于100刻度触发`THERMAL_OVERHEAT`并且失败tick产能为0；恰为100刻度仍安全。
10. A优先手写方案逐tick应与轨迹一致，十个tick均安全，产能56、水源520刻度、旁路损失4刻度、峰温94刻度、末态`[94,80,50]`。
11. 动态轮换手写方案逐tick应与轨迹一致，十个tick均安全，产能59、水源570刻度、旁路损失8刻度、峰温94刻度、末态`[94,84,30]`。
12. 精确边界手写方案完成十个安全tick后产能应为15，终止码为`PRODUCTION_TARGET_MET`；14分则必须以`PRODUCTION_BELOW_15`失败。
13. F01应在第二个热更新区间使A达到110刻度并过热；F03应按有损旁路逐步推进并在tick2使A达到106刻度，区分过热原因轨迹。
14. B01源水精确用满60刻度且各区不过阀时接受；B02产能精确15成功；B03超区阀时所有本帧更改原子拒绝、时钟不前进。
15. 同动作表seed0重复执行两次，Observation、读数、温度、流量收据、热状态、产能、终止原因和Oracle字节均须完全一致。Oracle只能作为公开逐步示例，不可作为Agent输入或未来泄漏。
