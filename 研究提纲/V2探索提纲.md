## 0. 总任务与研究定位

### 0.1 核心研究问题

**在确定性/可控随机、部分可观测的长程工具任务中，能否利用结构化记忆、基于公开事实的动作约束与自主阶段推断，使 Agent 在不知道预设路线/隐藏状态的情况下，以更少的动作和 Token、更高的有限预算成功率完成未知任务？**

将研究拆为四个可独立验证的问题：

- **RQ1（记忆）**：有选择的结构化记忆，是否比现有 Memory v2 更好地保存关键事实、记住负反馈、减少重复探索？
- **RQ2（动作接地）**：基于公开事实推导的工具适用性及条件化失败约束，能否减少合法但无效的动作，而不偷偷给出正确路线？
- **RQ3（自主分解）**：取消世界预置 `PublicMilestone` 的物品名称和阶段顺序后，Agent 能否仅依据经历推断当前任务阶段？
- **RQ4（泛化）**：上述收益是否能跨随机实例、任务依赖结构以及不同模型复现，而非只在已调整过的世界或单一 Muse 上成立？

### 0.2 V2 最重要的评价标准

**主指标**：`Success@30/60/100`（必要时 `@150/@200`）、第一次真实运行的成功率、执行动作数、**Token/成功局**、**墙钟时间/成功局**。  
**副指标**：参考最短路径倍率、无状态进展动作占比、重复失败动作、重复读码、终点错误工具、环路、已知事实丢失、阶段推断正确率（仅离线评分）、输入/输出 Token、provider 异常。  
**报告要求**：均给出每局结果和分布（均值/中位数/P90 或最大值），**不能仅报告平均值或不限步数成功率**。

> **严禁将** `step_limit=0` 下最终完成、经过网关中断补跑的「至少成功一次」，写成「首次尝试稳定通关」。`provider_error`、被中断/删失（censored）、动作错误、step_limit 必须分开记录；无证据不能填 0。

### 0.3 明确非目标

- **不继续靠“多建地图、多跑几百局”证明进展**；不重复已有的 45/45、105/105、150/150 或 flex/seeded 全量实验。
- 不优先实现 PlanningAgent v2、ReflectionAgent、多 Agent 编排、RAG、向量数据库、MCP、商业化后台、完整可启动实验的 Streamlit UI。
- 不以堆 prompt、调参或让模型背路线冒充算法创新；禁止将 world-declared guidance 与纯观察自主能力混在一起。
- 不修改旧世界和旧 Trace 来制造新基线；每次改变 world 定义必须版本化并留 hash。

### S1.3 离线重新计算

## S2 — MemoryAgent v3：可解释的结构化状态/记忆（优先级 P1）

### S2.1 核心目标与边界

在不增加预定义地图攻略的情况下，让 Agent **记得更多关键公开事实、忘掉无价值重复、追踪已探索空间、控制上下文体积**；必须能与 Memory v2 只改变记忆表示/更新策略而公平对比。

不要一开始完整重写 MemoryAgent。优先在已有 `MemoryReducer`、MemoryState、Runner 和 trace 机制上增加带版本号的独立策略，能通过开关在 v2/v3 之间切换。原 `memory` 运行行为默认不变，保证可复现。

### S2.2 拟探索的四类记忆（先设计字段，再按证据选最小子集）

| 记忆类别 | 来源（仅公开） | 作用 | 注意事项 |
|---|---|---|---|
| **Spatial** | 当前房间、公开出口、历史 `move` 的目的地/结果 | 已知拓扑/可探索前沿、减少无效回路 | 不可读完整地图 JSON 或环境私有邻接表 |
| **Episodic** | Observation–Action–ToolResult、时间/步骤索引 | 追踪尝试及失败原因、压缩最近事件 | 不持久化原始思维链或秘密 |
| **Task** | 已公开的任务目标、成功结果、自己观察到的依赖 | 区分完成/待完成、处理阶段反转 | 禁止从 `PublicMilestone` 注入未知物品名作为自主证据 |
| **Constraint** | 已公开的工具拒绝、依赖不满足及其条件 | 失败避免、环境变化后解除禁令 | 必须是**条件化**约束，禁止永久拉黑可在之后成功的 Action |

建议记忆事实最小记录：`fact_id`、`content`、`evidence_step`、`source_type`（observation/toolresult/inferred）、`confidence`、`preconditions`、`last_seen_step`、`status`（active/stale/invalidated）、`size_estimate`。推断事实必须标注推断性质，不能与直接观察事实同级。

### S2.3 三条候选研究机制（严格顺序探索）

**M1：Spatial + Causal Event Memory（优先）**  
保存已知房间与公开连边、待探索出口、已发生的因果事件（例如「电源已恢复」），让 Agent 根据事实判断当前已解决事项。**不主动提供目标位置和最佳路径**。  
**M2：Value-Aware Memory Selection（随后）**  
在固定上下文预算内，仅保留与未解决目标、最近失败和导航有关的条目；相较简单 H5，比较事件摘要/去重/过期机制是否减少 token 和循环。  
**M3：Condition-Aware Memory Invalidation（可与 S3 协同）**  
已知失败的动作在前提条件未变时标记为无效；前提变化（如供电恢复、物品入包、门开启）时可重新尝试。先验证自动测试，避免把本来可以成功的行动永久封禁。

### S2.4 离线测试与实现验收

- 同一完整 trace 回放得到一致 v3 memory digest；不同 episode 重置彻底，无跨局事实泄漏。
- 仅从公开 Observation/ToolResult 更新，不调用 environment 私有字段。
- 房间回程、已读码后移动、阶段顺序反转、未完成前置条件被修复、错误事实纠正均有 fixture。
- Memory 大小上限明确（例如字符/token 预算），超限不能静默丢关键已公开事实；提供 memory statistics（插入/更新/失效/压缩次数和估计 token）。
- Trace 与 provenance 可标识 `memory_schema_version=v3` 及机制开关，旧 trace 仍可读取；不改变基准世界、Action schema 和 E1 基线。

### S2.5 实验矩阵（渐进）

| 条件 | Memory | E1 | H/R | Phase | 用途 |
|---|---|---|---|---|---|
| **B-M** | v2 | ON | 固定 H5/R1 | world-declared ON | 现有胜出基准 |
| **M1** | v3-SpatialEvent | ON | 相同 | 相同 | 测新状态记忆 |
| **M2** | v3-Selective | ON | 相同 | 相同 | 测价值选择/压缩 |
| **M3** | v3-Invalidation | ON | 相同 | 相同 | 测条件过期（如不与 S3 重复） |
| **M+** | 只组合已有效候选 | ON | 相同 | 相同 | 测增益是否互补 |

**建议 pilot**：先选 S1 中「迷路长尾」与「遗忘关键事实」各一张图，保持模型与 B=60/100；每条件约 2–3 局。若出现可解释的 `Success@K` 提升、重复动作明显下降或 Token 改善，再扩到 2–3 种任务与 3–5 局。保留每局 Trace；失败也进入结论。

### S2.6 判定 Gate

- 不能仅凭「记忆字段更多」宣布成功。至少观察到一个**稳定方向**：同预算成功数改善、无效循环显著减少、P90 降低或 `token/success` 下降，同时没有导致非法动作、错误事实增多。
- 如果 M1/M2/M3 无收益，保留最小架构改进/审计成果，**不强制合并 M+**，进入 S3。
- 产物：`docs/research/v2/03-memory-v3.md`、最小 spec（如实际改变接口）、单变量矩阵、测试和可审计 Trace 索引。

## S3 — Action Grounding：让动作正确且有进展（优先级 P1）

### S3.1 目标与现有成果边界

V1 的 E1 已证「通用工具语义」可以减少 `read_terminal` 误用；本阶段**不重复 E1**。在 E1-ON 的共同基准上探索更普适机制：公开信息下的动作适用性、条件化失败约束和低成本恢复。

要研究的是：**模型已经知道哪些事实，却仍然作出不合理的 Action？最小额外反馈能否改变接地质量？**

### S3.2 候选机制与风险

**A1：Public Affordance Grounding**  
从当前公开 `Observation`、已执行 `inspect` 或公开工具结果维护「动作-目标可用性」。例如工具作用于某类对象的要求必须来自**已经呈现给 Agent 的公开描述/反馈**，不能读 `worlds/*.json` 中未暴露的 `kind`，不能因为内部私有图知道终点载具类别。若现有 Observation 缺少表达 affordance 的公开字段，先设计**向后兼容、版本化、无隐藏状态**的公开观察契约；旧基线保留。

**A2：Conditioned Failure Suppression**  
为同一公开状态下已经证伪的 `(tool,target,item)` 增加临时负约束；条件变化后自动解除，不能把先缺电的终端永久禁用。比较「只提醒」与「请求动作前轻校验并允许模型重新选择」；两种方式必须分开记录，以免暗中替代模型决策。

**A3：Progress-Triggered Recovery**  
针对重复 `look`、已知无效动作、环路和多次无状态/知识进展，输出短的**诊断性**公开反馈，如「当前动作未提供新信息」；不能直接提供最优下一步、真实路线或未来任务关键物品。若运行时直接给唯一下一动作，**应归类 assisted，不得作为自主结果**。

**A4（可选，不优先）**：只在 A1–A3 证实改善后，尝试记忆与动作候选联动；不引入第二次模型调用的高成本 Reflection 作为默认实现。

### S3.3 离线必测边界

- 首次失败与重复失败区别；`NO_POWER` 后供电恢复应可重新 `read_terminal`。
- `pickup` 必须经过公开可见性、`move` 必须在公开出口；`use` 的授权码可能来自已读 ToolResult，不要求是背包物品。
- 退回原路不等于导航循环；观察新增出口不等于无进展。
- 深海、灯塔、飞船和 flex 反序图中，同一工具可能作用于不同对象；任何代码级硬编码地图 ID/具体路线均视为失败。
- 记录动作被拒、重试、候选被过滤、实际模型选择和最终环境结果；**不能悄悄替 Agent 执行动作**。

### S3.4 在线单变量比较

固定 **Memory v2 或已验收的 Mv3（明确写版本）+ E1 ON + 相同 H/R/P 和预算**；依次只打开 A1、A2、A3，Pilot 取 S1 中真实有相关错误的地图和 seeded/flex 代表实例，不跑问题已消失的整套固定图。

分别报告：`WrongToolRate`、`RepeatedFailureRate`、`NoProgress@K`、`Success@K`、平均/尾部动作、Token/成功局、额外模型调用次数。仅降低错误却导致永远无法完成任务的候选不得算有效。

### S3.5 判定 Gate

- 输出 `docs/research/v2/04-action-grounding.md`：每个候选有真实步骤级前后证据、成功/失败记录、开销、是否污染自主性分级。
- 若 A1/A2/A3 都不显著改善，在无高成本修复前**停止继续堆 prompt/规则**，转向 S4 检验真正障碍是否在阶段理解。

## S4 — 自主 Phase：减少 world-declared guidance 依赖（优先级 P1，关键学术问题）

### S4.1 为什么必须做

当前 `PublicPhaseTracker` 从世界预置里程碑生成阶段与目标物品提示；在尚未探索之前即可知道工具 ID 和「收集→修复→读码→逃生」大致顺序。它不直接暴露 WorldState，却是明显的**任务先验**。不可以用当前 150/150 证明「完全自主发现任务结构」。

V2 的挑战是：**只用当前及历史的公开经历维护阶段，不提前知道世界声明的关键工具、前置条件和任务顺序。**

### S4.2 三条严格分级路线

| 层级 | 上下文来源 | 是否允许未知目标名/阶段顺序 | 研究定位 |
|---|---|---|---|
| **P0：No Phase** | Observation + Memory/H/R | 否 | 无阶段提示的下界 |
| **P1：Observation-derived Phase** | 已观察到的 ToolResult、背包、可见对象及其证据 | 否 | **V2 主目标** |
| **P2：World-declared Phase** | 既有 `PublicMilestone` | 是 | 当前可靠性上界/辅助对照 |

可选 P1a：规则事件摘要（零新增 LLM 调用）；P1b：模型从可观察证据推断阶段（若增加 API 调用，明确计入总 Token/延迟，且提示不得看到隐藏里程碑/oracle）。先 P1a，若失败再研究 P1b。

### S4.3 实现建议

- 建立 `ObservedTaskState`：`observed_goals`、`completed_public_events`、`unsatisfied_conditions`、`uncertain_hypotheses`、`evidence_refs`、`next_information_need`；禁止注入未被观察到的工具、房间或顺序。
- 对环境反馈 `NO_POWER`、`MISSING_ITEM`、`CODE_READ`、`CELL_STAGED` 等增量更新；阶段「尚未可判」是合法状态，不得乱猜完整任务路线。
- 如果采用 LLM 提取阶段，其输出是**可解释推断**而不是 Environment 的事实，带置信度和来源；错了能够用 ToolResult 纠正。
- `PublicPhaseTracker` 旧版保持冻结；新模式使用独立名称、prompt_hash/phase_version/feature flag，且与 Mv3/A1–A3 的耦合受控。
- 对于 flex「先读码」「分支供电」「并行收集」等，验证推断器不固定套用经典五步谜题链。

### S4.4 先做最关键的公平对照

固定模型、世界实例、E1、H/R、Memory（使用先前 Gate 选定版本）和步数预算：

1. `P2`（world-declared 基线）；
2. `P0`（无任何阶段）；
3. `P1a`（纯公开事件提取）；
4. 仅若必要，`P1b`（LLM 推断且成本单列）。

初期在 1 个原经典任务、1 个 seeded、1 个 flex 反序/并行任务中各做小 pilot；**不要首先在 30 张已知图全量刷分**。训练调优用开发实例，最终评测在事先锁定的隐藏实例。

### S4.5 真正的成功是什么

优先看 `P1` 相比 `P0` 提升多少、相比 `P2` 损失多少，并解释损失是因为未知前置条件、错误推断还是环境交互。**即使 P1 暂时比 P2 差，也可以形成有价值的定量发现。**

需要报告：阶段准确度/稳定度（仅评价器离线判）、未知事实幻觉次数、阶段错误切换、回退/纠正能力、`Success@K`、Token 和长尾。

交付：`docs/research/v2/05-autonomous-phase.md`、Phase 来源追踪测试、泄漏防护测试、至少一个真正反序任务的完整 Trace 对照。

## S5 — 跨任务、随机实例、跨模型验证（优先级 P2，论文与平台化的分水岭）

### S5.1 目标：从「通关更多地图」变成「有可测试的泛化」

只对在 S2/S3/S4 获得正面证据的候选做跨域确认。用 V1 建好的 10 世界和 flex 引擎，但把以下层次分开：

1. **同一固定实例重复运行**：只测行为采样的重复可靠性；
2. **同规则、不同 seed 实例**：如物品位置、岔路/障碍、诱饵变化；
3. **同一工具集、不同任务依赖结构**：顺序/并行/分支/反转；
4. **真正不同规则/目标与反馈机制**：如可消耗资源、动态事件、多目标冲突；
5. **不同模型与 provider**：测架构可迁移性而不是只测 Muse 适配。

### S5.2 优先扩展 seeded 长尾，而非地图数量

针对现有 159/232 步长尾，先离线切分：额外路程、反复询问、物品重访、阶段错误和工具重试各占多少；区分**oracle 路径本身变长**和 Agent 无效行为。只有确定瓶颈后才改变随机分布或模块。

Seeded 世界应确保：同 seed 生成相同实例、不同 seed 有足够多不同实例哈希、每实例确有可行解、预定义难度和实际 oracle 长度可计算。**为测试泛化而生成实例，不要为了让模型成功而剔除困难 seed。**

### S5.3 新任务不是单纯换背景

优先用已有 flex 引擎构建 **一个** 小而真正不同的规则族，例如：

- **资源约束**：有限氧气/电量/工具使用次数，必须在有限成本内到达目标；
- **动态故障**：任务执行中某设备失效，必须依据新增 ToolResult 更新原计划；
- **多目标冲突**：两个目标共享资源、存在可逆/不可逆决定，无法按照固定五阶段路线机械操作。

先选最小规则改动、明确不变量和新 oracle；如果要改 Tool schema，建独立任务族并做协议迁移试验，不为了“多样化”破坏旧世界。

### S5.4 开发集/测试集与防数据泄漏

- 在开发前冻结 `world_version + instance_hash` 分组；开发集可用于 S2–S4 调整，测试集**不得参与调提示词/机制**。
- 保留固定经典任务作为回归集、seeded 作为实例泛化集、flex 作为依赖结构泛化集、新规则任务作为外推集。
- 阶段生成器不能接触测试实例答案；oracle 只供测试/评分。测试集表现差也如实报告，不回头改测试地图直到取得成功。

### S5.5 多模型比较设计

模型选择：**Muse（主开发基线） + 至少一个有稳定访问渠道的独立模型**（如本地 Qwen/其他可用 API），如预算和硬件允许再加第三个；不虚构已连接模型。采用相同任务实例、相同观测/action 契约、相近输出约束、统一步数预算和日志格式；API 能力差异单列。

建议最小矩阵（不是无限扩张）：

| 因子 | 最小设置 |
|---|---|
| 机制 | `B0`（E1+Memory v2+现有 H/R/P2）、`Best-M`、`Best-A`、`Best-Phase(P1)`、`Best-Combined`（只保留真正通过 Gate 的行） |
| 世界 | 1 个经典固定 + 1 个 seeded + 1 个 flex/新规则任务 |
| 实例 | 每类 3–5 个已冻结的实例/运行尝试，清楚说明相互独立性 |
| 模型 | Muse + 1 个独立模型，两个模型分别报告 |
| 预算 | 主比较 B60/B100；若超限较多，可加 B150 作次级，不设无限步作为主要 KPI |
| 指标 | first-attempt Success@K、Token/成功局、动作数、oracle 比、失效类别、provider-error、跨模型效应方向 |

对于无法在有限预算内取得成功的模型，报告阶段进展和错误分布，不把 `token/success` 写成零或无穷大而不解释。

### S5.6 稳健性检查与停机规则

- 先 1 局 smoke 确认 provider/schema/工具链，再做正式实验；正式 run 的世界/模型/hash 在启动前冻结。
- 模型网关限流时自动降低并发；记录所有失败尝试和重试成本。
- 候选机制在开发集明显没有改善时，不展开完整多模型矩阵。
- 若某模型不支持所需工具输出模式，给出不兼容分析，**不可暗改 Prompt 而仍称同条件比较**。
- 只把已执行的测试与结果写为 `done`；未跑的规划保留 `planned/blocked`。

交付：`docs/research/v2/06-generalization-and-models.md`，可再生实验脚本、实例划分 manifest、完整指标表和模型差异说明。

2. **随后 S1（首选全离线）**：恢复实验台账、优先分析长尾与已知失败，确定最有价值的 2–3 个机制假设；先给出 `02-bottleneck-audit.md`，不要直接开始跑模型。
3. **S2 Memory v3**：优先 M1 空间/事件记忆，接着仅在有证据时做 M2/M3。每个候选先测试、再受控 pilot。保持 V1 Memory+E1 胜出配置可复现。
4. **S3 Action Grounding**：从 S1 尚未被 E1 解决的错误出发，先 A1/A2，再决定 A3；严格无隐藏状态、无答案式工具建议。
5. **S4 自主 Phase**：P0/P1/P2 严格区分。以 P1（observation-derived）为真正研究目标；将当前 P2 明确视作带世界预置任务先验的可靠性上界。
6. **S5 验证**：仅携带过 Gate 的机制，冻结随机实例/新任务测试集，做有限步数跨任务和至少两个真实模型的独立对照；如果没有第二模型访问，保留 blocked，不假称完成。
7. **S6 收官**：生成 SUMMARY、所有实验表、失败/反例、提交和远端 CI 证据，提出 V3 的**一个**最有潜力的问题，而不是自动新开大量任务。

### 必须遵守的停止原则

- 不因为 GPU 或 Token 空闲而重复大量低信息实验；不能通过无限步数重试，把初次失败刷成 100%。
- 每阶段**先判定研究收益，再投入下一阶段**。阴性结论同样是合法交付。
- 用户已经明确方向，**不需要为了小的实现细节反复询问**；如发生必须额外花费明显超出本提纲 pilot 规模的模型调用、新模型收费/凭据权限缺失、需要修改历史基线或不可逆操作，记录阻塞并停止该分支，不要自行扩大预算。

---

## 8. 期望 V2 达成的研究里程碑

**保底成功**：CI 全绿 + 全部历史可靠性口径清晰 + 找到真实长尾根因 + 完成至少一个 Memory 或 Action 的严格单变量实验 + 给出 P0/P1/P2 的诚实对照，即使全部新机制无提升也有可信研究结果。  
**理想成功**：在**有限预算**下找到一个可解释、可跨实例/跨任务迁移的低成本机制，使 `Success@60/100` 和 `Token/成功局` 在多个任务上持续优于冻结的 V1 E1 基准；同时显著减少对 world-declared Phase 的依赖。  
**不作为成功依据**：堆积世界数量、无限步通过率、刷补跑成功、展示型 UI、大量 prompt 版本或未经受控比较的架构复杂度。

> **最终定位**：将 Agent-Arena 从「可通关、可回放的 Agent 实验场」推进为「研究结构化记忆、状态感知动作执行与自主任务分解的可复现长程 Agent Benchmark」。
