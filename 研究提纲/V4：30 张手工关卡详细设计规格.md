# V4：30 张手工关卡详细设计规格

> 项目：Agent-Arena｜版本：V4.0 DESIGN FREEZE DRAFT｜用途：交付 6.1 Luna 的**人工关卡规格**，而非自由生成提示词。  
> 状态：**设计蓝图，非已经实现或通过求解验证的事实**。文中数值为首版候选参数；在离线可解性验收通过前不得宣布关卡定稿。  
> V3 保持只读作为对照；V4 独立实现，不复用 V3 的固定答案和评分结论。

## 0. 设计目标和不可妥协的原则

1. **能力先于主题**：每关先有可证伪的能力假设，再有空间、机制和故事。不能仅因为出现对话就称为“社交能力”，或因为步数多就称为“长期规划”。
2. **30 个独立任务内核**：十个世界仅共用视觉叙事背景；同世界三关的主测能力、动作约束、失败因果、信息结构应有实质区别。
3. **手工内容冻结**：节点、边、物品、因果方程、证据表、时间窗、事件触发、目标谓词、失败谓词必须按本规格显式实现；不得用随机房间/通用谜题模板自动补全。
4. **生成只用于验证后的受控变体**：只允许交换经过证明不改变核心能力的参数、拓扑同构或语义等价线索；每个变体独立验收可解性、唯一性和难度。
5. **不泄露答案**：Agent 只能看到当前位置、合法观测、已执行动作反馈及自身日志；内部状态、真值表、最优动作、评分函数实现不进入观测。
6. **可重复、可解释**：同种子同动作序列得到完全一致的状态、日志和结果；每一步有原因码与状态差分；裁判不调用 LLM 判断对错。
7. **至少两类成功策略**：对有自然多策略的任务保留可比较的非支配方案；纯逻辑题允许唯一答案，但应允许不同的求证顺序。
8. **区分能力与干扰因素**：同一能力测试应设置可控对照（有无记忆、额外观测、完整计划、故障提前告知等）；不把地图大小、文本长度或工具接口复杂度当作能力本身。
9. **安全失败与可解释失败**：明确不可逆失败、可恢复错误、时间/资源耗尽；失败日志须能归因到具体机制，不能以隐藏任意规则惩罚 Agent。
10. **拒绝伪难度**：禁止仅通过增加无意义行走、改变量级、随机锁死、重复操作或增加 token 噪声制造 Hard。

## 1. 统一执行契约（所有地图强制）

### 1.1 状态与时间
- 状态 `S=(map_id,seed,tick,location,public_state,private_state,inventory,history,terminal)`。所有状态转移为 `S_{t+1}=T(S_t,a_t,seed)`，禁止墙钟时间与不可控外部 API 影响环境规则。
- 每个合法动作默认消耗 1 tick；`inspect` 是否耗时必须在关卡动作表声明；失败动作默认消耗 1 tick，避免无限探测漏洞。跨多边移动禁止一步瞬移。
- 环境事件在 **动作效果提交后、tick+1 时** 统一触发；个别需要先结算的关卡必须在规则中显式覆盖，并在单测验证。
- 观察返回：当前区域、可见出口、可见对象、局部状态、合法动作 schema、上一动作结果、可公开的任务目标；绝不返回 `private_state`。

### 1.2 API 最小集合
`observe()`, `move(edge_id)`, `inspect(target_id)`, `interact(target_id,operation,arguments)`, `wait(ticks=1)`, `note(text)`（Agent 自己的记忆，不改变环境；不能让裁判读取 note 判成功）。世界特有操作使用严格枚举 schema，参数错误返回明确错误码。

### 1.3 评分
- **主指标**：按关卡定义的能力结果（如推理正确率、调度差距、记忆召回）。
- **硬约束**：安全、资源、时间、合法性；违背后不能通过加分掩盖。
- **辅助指标**：步数、资源消耗、信息成本、无效动作、状态回退、证据覆盖。
- 不以 `oracle_steps` 单独定义难度；oracle 是可行性证据，不是 LLM 的成功率预测。
- 多目标关卡报告原始指标与 Pareto 前沿；如需总分，必须公开权重及敏感性分析。

### 1.4 数据与审计
每一步保存：`step,action,arguments,pre_state_hash,observation,delta,event_id,reward_components,post_state_hash,reason_code`。保存环境版本、seed、任务参数、模型版本、推理配置、提示词摘要、token/费用/时延。

### 1.5 设计审查门槛
- 拓扑连通性、可达性、时窗可满足性、资源守恒、状态边界、死锁检测。
- 对逻辑题做枚举/SMT 唯一性验证；对调度/资源题做优化器上界；对动态题做模型检查或状态空间采样。
- 关卡必须至少有一条 **手写、可回放的成功轨迹**；有多策略承诺时至少两条不同策略族轨迹。
- 必须有至少三条 **手写失败轨迹**：误判、贪心局部最优、未更新计划/记忆（按关卡调整）。
- 自动测试覆盖每一动作前置条件、边界值、失败码、事件顺序和重放哈希。
- 关卡未通过这些门槛，只能标记 `DESIGN_PENDING`，禁止宣传为“已验证可解”。

## 3.1 飞船｜长期规划与执行监控

### MAP-01｜01 破损的曙光号

- **核心能力**：前置依赖规划。
- **拓扑与区域（人工固定）**：舰桥 B—环廊 H—{动力 P、供氧 O、维修 W、气闸 A}；W—受损捷径—P，捷径初始封闭。
- **初始状态与私有变量**：位置B；电池6格；氧气余量18 tick；主电源关闭；补丁在W；维修臂需2格电；循环供氧需2格电；气闸关闭。
- **允许的核心动作**：查看配电图、走动、分配电力、取补丁、启动供氧、维修外壳、复位动力、返舰桥。
- **转移与事件规则**：必须先供氧稳定，再取补丁并维修外壳，最后恢复主动力；供电不能同时支持供氧与维修臂，允许临时切换但供氧停机最多3 tick。
- **成功 / 失败谓词**：外壳完整且主动力恢复、舰桥完成确认；氧气归零或连续供氧停机>3 tick失败。
- **多策略设计**：先完成供氧并缓存氧气再切换；或先走长廊准备维修工具，区别在移动成本。
- **核心测量**：依赖违例数、无效电力切换数、总步数。
- **因果对照与防作弊**：对照：给出依赖图与不给依赖图；保持路径长度相同；验证依赖推理而非寻路。
- **必须手写的验收案例**：一条成功轨迹、三条有具体动作的失败轨迹、一个边界状态案例、一个种子重放案例；开发前把上述自然语言规则落成 `map_spec.yaml` 和 `oracle_trace.jsonl`，且人工复核。
- **禁止的简化**：不得把任务改为“收集N个物品后到出口”，不得使用通用倒计时替代本关特有机制，不得在观察中暴露真相或未来事件。

### MAP-02｜02 双重警报

- **核心能力**：事件触发后的重规划。
- **拓扑与区域（人工固定）**：左区 L1—L2—中闸 C—右区 R1—R2；C 可单向锁定；救生舱 E 在R2。
- **初始状态与私有变量**：位置C；导航核在R1；船员在L2；维修包1；剩余20 tick；初始警报仅导航故障。
- **允许的核心动作**：检查警报、隔离舱、取维修包、修核、救人、打开应急通道、撤离。
- **转移与事件规则**：完成第4个有效动作时L1发生真实泄漏，L区倒计时8；若先锁C可阻止扩散但需从外侧绕行救人。
- **成功 / 失败谓词**：船员撤至E且导航核封存；L区失压前未救人或核损坏失败。
- **多策略设计**：立即改救人优先；或先封存导航核再通过应急通道救人，前提时间可行。
- **核心测量**：重规划延迟、旧计划动作残留、双目标完成率。
- **因果对照与防作弊**：对照：无突发事件；相同事件但提前通知；不能通过观察直接读出最佳策略。
- **必须手写的验收案例**：一条成功轨迹、三条有具体动作的失败轨迹、一个边界状态案例、一个种子重放案例；开发前把上述自然语言规则落成 `map_spec.yaml` 和 `oracle_trace.jsonl`，且人工复核。

### MAP-03｜03 最后的百步

- **核心能力**：长时程目标保持与阶段记忆。
- **拓扑与区域（人工固定）**：双层舰：下层能源D1—仓库D2—维修D3—升降机X；上层科研U1—舰桥U2—通信U3—X；外部EVA区V从D3进入。

- **允许的核心动作**：记录日志、取样、修供电、EVA、发送遥测、校准航线、返航。
- **转移与事件规则**：五阶段依赖：供电→样本冷藏→EVA天线→遥测→航线；早期K7在最后校准使用；阶段完成后观察摘要不再自动重复K7。

- **多策略设计**：按区块减少往返或按里程碑减少记忆负担，两条可行路径。
- **核心测量**：阶段遗漏、早期信息召回、每20步偏离目标次数。
- **因果对照与防作弊**：对照：完整历史/短上下文/外部记忆；避免把冗长路径当作记忆难度。

## 3.2 灯塔｜时间窗口与不确定决策

### MAP-04｜04 潮汐密道

- **核心能力**：周期预测。
- **拓扑与区域（人工固定）**：灯塔T—台阶S—礁洞G—码头D；S-G只在潮相0,1开放；T-D绕路5步。
- **初始状态与私有变量**：潮相2/6；时限18；灯芯在G；灯塔缺灯芯。
- **允许的核心动作**：观察潮位、等待、移动、取灯芯、点灯。
- **转移与事件规则**：每动作潮相+1模6；进入G后退潮可在G安全等待但不能穿越；返回须计算相位；绕路永远可通但耗时。
- **成功 / 失败谓词**：在救援船到达前点灯；时限耗尽失败。
- **多策略设计**：潮窗往返或绕路运输，时间成本不同。
- **核心测量**：窗口错失、等待步数、完成时间。
- **因果对照与防作弊**：对照：显示未来潮相表与仅显示当前潮相；验证时间推理。
- **必须手写的验收案例**：一条成功轨迹、三条有具体动作的失败轨迹、一个边界状态案例、一个种子重放案例；开发前把上述自然语言规则落成 `map_spec.yaml` 和 `oracle_trace.jsonl`，且人工复核。

### MAP-05｜05 三束信号

- **核心能力**：共享资源调度。
- **拓扑与区域（人工固定）**：中央供电C连接红塔R、蓝塔B、白塔W；R-B无直连；三塔到C移动分别1/2/3。

- **允许的核心动作**：移动、切换供电、校准、发送、查看航表。
- **转移与事件规则**：校准状态断电保留；发送必须占窗口且已供电；切换供电耗1 tick；每塔独立发送一次。

### MAP-06｜06 暴风眼

- **核心能力**：信息价值与风险决策。
- **拓扑与区域（人工固定）**：主楼M—气象台Q—维修平台P；M—备用机房G—P；Q提供预测，G提供防护。
- **初始状态与私有变量**：天气隐藏类型{短暴风、长暴风}；先验各0.5；维修需2 tick；风险预算4。
- **允许的核心动作**：查预报、加固、等待、走动、维修、撤离。
- **转移与事件规则**：查预报耗2 tick且有80%准确率；防护耗3 tick、维修受伤风险降低；天气类型由seed固定，不可在行动后改写。

- **多策略设计**：立即维修、先测后修、先防护后修均有不同期望收益。
- **核心测量**：期望损失、信息成本、风险违规。
- **因果对照与防作弊**：报告不同先验下策略；评分按已公开的期望效用规则，不以某次幸运结果判能力。

## 3.3 深海｜因果诊断与动态系统控制

### MAP-07｜07 逆流阀门

- **核心能力**：因果后果预测。

## 5. 反换皮验收：五种必须同时成立的差异

1. **拓扑差异**：图的关键结构和行动含义不同（环、瓶颈、时变边、分层区域、共享资源区段等）；不只换节点名。
2. **信息差异**：不同关卡的隐藏信息、可观测性、可查询成本不同；不只换线索文本。
3. **决策差异**：核心选择是排程、诊断、推理、探索、控制、风险、记忆中的不同机制；不只换目标物。
4. **失败差异**：有机制专属的可解释失败原因；不只统一为“倒计时归零”。
5. **测量差异**：主指标与能力对照不同；不只复用同一成功率排行榜。

任意两张地图如果上述五项中有三项及以上实质相同，必须触发人工复审。地图外观不同不计入实质差异。

## 6. 难度与实验协议

### 6.1 不是预设 Easy / Medium / Hard 的成功率
这 30 关按能力主题递进，但**不能未经实测就声称编号越大越难**。记录理论最优动作数、最少信息查询数、可行策略数、不可逆决策数、必要历史跨度、分支因子、观测熵；这些是难度描述变量，不是难度本身。

### 6.2 真实 Agent 评测矩阵
- 基础：同一模型、同一工具接口、同一推理预算，至少覆盖直接行动、先规划后行动、带结构化记忆三种 Agent 配置。
- 能力对照：记忆关比较短/长历史；规划关比较有无依赖提示；诊断关比较有无区分性检测；动态关比较有无提前故障通知；策略关比较不同风险预算。
- 避免污染：冻结公开开发关卡与隐藏测试变体，不能把参考轨迹或最终答案放进系统提示词。
- 记录模型对每关的成功率、资源成本、失败类型、动作序列；报告置信区间。重复运行数量由预算与方差决定，不能只用单次运行断言模型强弱。
- 如需综合排行榜：按能力维度分组宏平均，并同时公开逐关原始结果，避免某世界关卡数或尺度主导总分。

### 6.3 对照实验不能被错误解释
“完整历史优于短历史”只能说明**该配置在该任务上的性能差异**，不能自动证明模型具备通用记忆能力；需排除上下文长度、额外 token、工具使用方式等混淆。相同原则适用于规划、推理和反思。

## 7. 开发执行顺序与停机条件

### Phase 0｜仅设计，不写环境代码
- 把本文 30 关拆成 30 个设计工单；逐关补齐精确数值、可执行谓词、手工动作轨迹。
- 首先检查所有规则是否存在自相矛盾、不可达、无解或伪唯一解。
- 特别注意 MAP-13 的逻辑约束：当前列的是**待形式化候选**，不得在枚举唯一性前固定为谜题答案。
- 产出 30 张地图的结构图（Mermaid 或 Graphviz 源码）、状态表和事件时间线。

### Phase 1｜高差异性原型（先做 6 张）
优先：MAP-03 长时程、MAP-08 主动诊断、MAP-16 调度互斥、MAP-22 空间记忆、MAP-26 自我纠错、MAP-29 证人可信度。它们覆盖六类不同任务机制，最容易暴露通用关卡引擎是否强行抹平差异。

### Phase 2｜剩余 24 关分世界实现
每关必须先提交规格与验收案例，再提交实现；不可一次性生成三十关后集中修 bug。共享代码仅限基础设施（动作校验、日志、确定性、观测过滤），禁止共享“通用谜题/通用通关流程”取代核心玩法。

### Phase 3｜能力有效性验证
执行能力对照、失败归因、跨种子受控变体与真实模型试跑。**未通过能力有效性测试的地图只能叫玩法关卡，不能宣称是该能力的可靠 Benchmark。**

### 必须暂停并上报的情况
- 规则冲突、无解或唯一解不成立。
- 存在比设计目标更简单的捷径（例如通过错误反馈枚举答案）。
- 需要增加未在规格中的随机事件才能制造难度。
- 需要改变主测能力、地图拓扑或胜利谓词才能实现。
- 不同地图出现高度重复的状态机与解法。
