## 1. 交付目标和优先级

V6 不以“更高通过率”为目标，而以**可靠识别能力差异**为目标。需要产出：
1. 六图 V5 失败分类与数据质量审计（包括截尾、动作无效、资源耗尽、规则理解、策略失败、模型格式错误）；
2. MAP-16/18/22 的测量有效性修复与至少三层难度实例，明确何种能力被减弱/增强；
3. MAP-08/26/30 的多实例泛化与公平配对消融，避免记忆、诊断、反馈等能力混淆；
4. 可运行、可确定复现的 V6 fixture / 环境版本、Oracle、独立求解器、无泄漏测试、离线评估报告；
5. 单独的**可选**真实 API 实验方案与预算门禁；不自动执行。

建议创建：`docs/specs/0019-v6-measurement-validity.md`、`docs/v6/README.md`、`docs/v6/v5-failure-audit.md`、`docs/v6/design-change-requests.md`、`docs/v6/measurement-matrix.md`、`docs/v6/validation-report.md`、`docs/v6/api-experiment-proposal.md`、`docs/v6/next-24-gate.md`。代码目录遵守现有仓库规范，优先最小增量，不另起一套不兼容 runner。

## 3. 六图逐项技术要求

### MAP-16：单线会车 / 约束调度（P0）

已知 V5：ReAct 0/3，constraint_table 1/3；多数失败来自避让站 D 的容量冲突、另有相向交换。

**必须做：**
- 建立最小状态模型，显式列出列车位置、方向、预约、站点容量、边占用、同步时间步的更新顺序、合法/非法操作、交换冲突、死锁与终止判定；用 BFS/穷举枚举小实例，证明可解并记录最优 makespan。
- 分层：L1 单列车/单次预约与容量合法性；L2 双列车避让但减少同步冲突；L3 完整 V4 同步调度。L1 不应被当作“会双车调度”的证据。
- 至少 3 个**结构不同且人工审阅**的测试初态/拓扑变体（不是仅换 seed 标签），每个保存实例 ID、规则版本和独立求解结果；确保对照条件在相同实例上配对。
- 指标：合法预约率、容量冲突率、交换冲突率、死锁率、完成率、makespan/最优差、无效动作成本、首次不可恢复错误步数。
- 对照：基础公开规则 vs **同信息量**的结构化约束表；不可在结构化表中泄漏下一步最优动作。
- 明确验证“容量约束是否可理解”与“多步调度是否可完成”两项独立能力。

### MAP-18：故障传播 / 在线重规划（P0）

已知 V5：alert_off 0/3、alert_on 0/3；服务率 0–0.33，均未达 70% 阈值，无法分离预警效果。

**必须做：**
- 使用离线求解器分别验证：无故障基线、固定故障但无预警、同故障且有预警的理论可达服务率、调度可行性和最小延误；如现有 70% 目标不可达，**先报告不可达并发 DCR**，禁止私自下调目标。
- 分层：L1 静态无故障调度；L2 已知故障后的局部改线；L3 在线不确定故障、有限预警和乘客积压的完整任务。
- 设计至少 3 个独立故障情景（不同闭塞段、发生时刻、持续时间/恢复模式），固定同一实例配对 alert_on/off；若预警对所有可行策略理论上无影响，应淘汰该对照或改情景。
- 指标：服务率、累计延误、恢复时长、故障后首次合法重规划 tick、无效路由、吞吐量、最优差；失败按不可达/策略失败/接口误读/预算截尾区分。
- **信息隔离**：预警只能披露预注册允许的模糊/提前信息；无预警条件不能从 prompt、ID、日志名称泄漏未来闭塞位置或时间。

### MAP-22：没有地图的森林 / 空间记忆（P0）

已知 V5：6/6 均到 100 步限制；共同合法前缀终点 L/tick12 后基本不再成功移动；因此目前不能推断“图记忆无效”。V5 还发现原设计 Oracle 预装未来拓扑的泄漏问题，不能复用为模型记忆。

**必须做：**
- 先从 trace（若可访问）或离线重演排查：合法边标识解释、Observation 邻接边编码、目标是否可见、返程策略、记忆记录的时机/容量、动作失败原因。**先修接口可读性，再改任务难度**。
- 分层：L1 已探索两三节点的返程；L2 部分探索图、需回溯与识别重复点；L3 12 节点原任务。每层起始状态必须由合法行动前缀实际生成，不能直接手填隐藏图记忆。
- 设计至少 3 个手工审阅的不同拓扑，改变岔路、环、死路分布，而非重命名节点；每个有最短路/探索下界与独立求解。
- 对照：history5 vs history5+合法外部图记忆；共同前缀、共同公开信息和动作预算。若 memory 条件额外提供未观察的边，判为泄漏。
- 指标：返程成功率、有效移动率、重复边比例、回溯正确率、地图事实准确率、与已知最短返程距离差、step-limit 截尾率。不能把“探索快”直接当“记忆好”。

### MAP-08：看不见的裂缝 / 主动诊断（P1）

已知 V5：假设表 3/3 vs 无表 1/3；B/D/F 各仅一实例，可能对固定测试签名过拟合。

**必须做：**
- 新增至少 3 个经过人工核验的独立诊断实例：改变传感器覆盖关系、候选漏点或测试成本；每个提供隐藏真值、观测签名矩阵、测试前后候选集、最小测试数和成功路线。
- 证明候选故障可被合法观测区分；避免单一测试直接泄漏答案、无解实例、测试成本使成功不可能。
- 同实例比较 hypothesis_table / no_table，**公开观察完全一致**；表只记录已公开证据与剩余候选，不能写入隐藏真值。
- 指标：诊断准确率、错误封堵、测试次数、信息增益、后验候选集大小、资源耗尽率；按实例配对记录，不把固定 seed 当独立实例。

### MAP-26：失败的维修计划 / 反馈纠错（P1）

已知 V5：free_diagnosis 2/3；recovery_full 1/1、recovery_structured 1/1、recovery_hidden 0/1；恢复条件仅单例且 hidden 是信息剥夺，不是等信息基线。

**必须做：**
- 分开 `diagnosis` 与 `recovery` 两种测量，禁止混合成一个“纠错能力总分”。
- 设计至少 3 个不同真实故障和**合法生成的失败前缀**；每个失败后必须保留至少一条可行修复路径与足够备件。若无法证明可恢复，标记无效 fixture。
- 等信息条件对照：同样的失败反馈原文、同样资源和公开历史，仅改变结构化整理/记录方式；另设 `feedback_hidden` 作为信息剥夺下界，不与等信息条件混同。
- 指标：失败后首个有效策略调整、重复错误率、剩余备件、诊断准确率、修复成功率、恢复额外动作数；记录是否因不可逆错误已无解。

### MAP-30：午夜审判 / 长间隔证据记忆（P1）

已知 V5：history_full 3/3、history5_casebook 3/3、history5 0/3；三 seed 为同一案情重复，且 A/C 从固定前缀只需 1 决策便可提交。

**必须做：**
- 设计至少 3 个不同案情与证据链，改变证人、矛盾关系、关键证据出现位置、证据解锁顺序、正确指控，避免仅替换人名。
- 使模型必须经历多步合法调查与跨阶段证据使用，不能只从固定前缀“一步提交”就宣称长期规划；保留一个固定前缀版本用于**纯记忆召回**，两种任务分开报告。
- 同案情比较 history_full / history5 / history5+casebook，A/C 可访问相同已公开事实，casebook 不得包含尚未解锁的证据、隐藏真值或 canonical 答案映射。
- 指标：关键证据召回、事实引用准确率、跨案件一致性、错误指控率、延迟步数、最终正确率、所用证据的可追溯性。

## 4. 跨地图统一测量规范

- **实验单位**：`instance_id` 表示独立环境实例；`run_id` 表示一次模型执行；`seed` 仅用于控制随机性。固定场景三次 seed 重跑不等于三个独立实例。
- **配对**：同一 instance、同一初态、相同公开信息、相同预算、同一模型版本/temperature/工具契约；只改变预登记的目标机制。
- **主要结果**：能力专属主指标（逐图定义）+ 通关率；同时报告非法动作、预算截尾、运行异常、资源耗尽。截尾不得默认为推理失败。
- **统计**：先输出逐实例、逐条件、逐次运行的原始计数与配对差；实例不足时不做显著性断言，不给不合理的独立样本置信区间。多实例扩大后再选用配对自助法/置换检验，并按实例聚类。
- **难度**：L1/L2/L3 必须说明降低了什么能力负担、保留了什么核心机制，避免只增大步数上限或降低胜负阈值。
- **泄漏**：所有公开提示与 Observation 必须由 public state 构建；加入反例测试，检查 seed、内部答案、Oracle 路线、未解锁证据、未来事件不会出现在 prompt/trace 中。
- **模型接口**：保留严格 Action 校验和既有 `tool` 键契约；只允许解释公开编码，不允许提供“最佳下一步”暗示。若需更新提示，必须同时重新冻结基线和对照。

## 5. Phase 1：先实现零付费的诊断与独立求解

建议先做六图统一的 `audit_v5_failures.py`（如 artifacts 不存在，则只读已有报告并明确 `trace_unavailable`）、`validate_v6_instances.py`、`validate_v6_leakage.py`；命名可按仓库约定调整。

instance_id: map16_l2_siding_variant_a

4. 有三种有意义的失败/边界案例（如非法预约、超资源、错指控）；
