# V7：30 张地图分层能力评测与指标体系——逐图手工设计执行提纲

> 交付对象：DeepSeek V4.1 Flash；项目：`wenxvn/Agent-Arena`。编制日期：2026-10-16。此文档是**执行规格与人工设计候选**，不是已完成实现或实测报告。以执行时仓库 HEAD 为准，记录 SHA、工作区状态与冲突；不得假装已运行未运行的测试。

## 0. 一句话任务与不可妥协原则

**为 10 种世界风格 × 3 个预设难度 = 30 张不同机制的手工关卡，逐关建立可解释的能力构念、专属指标、确定性计分器、验证案例及评测协议；先在已有六张可运行地图上落地，再逐图审核其余 24 张。**

- **禁止批量生成地图、换皮复用关卡、同一评分公式套 30 张图**。本提纲每张地图都有单独设计条款；执行者必须逐张核对 V4 原始规格并做实质性人工设计/审查。允许共享日志基础设施、类型系统、校验器，**不允许共享一套机械玩法或复制粘贴的能力说明**。
- **禁止把“简单、中等、困难”理解为可直接跨世界比较的同等难度**。MAP-01/02/03 是同一世界的三张不同关卡，MAP-16/17/18 亦然；难度标签是设计定位，须由认知负荷与后续实测校准，不能把 MAP-01 的步数与 MAP-16 的步数比较。
- **不要以模型是否通关、总步数作为唯一评估**。每图必须至少一个核心连续指标、一个安全/约束指标、一个失败归因指标，另有成本指标；核心指标须从真实状态转移和 trace 确定性计算，不能由 LLM 主观打分。
- **历史不可改写**：不覆盖 V2/V4/V5/V6 的 Oracle、设计文档、实验账本、注册表和原始 trace；变更规则须新版本 + DCR + 回归。V6 29 个实例仍 `pending_human_review`，执行者不能自称完成了人工审核。
- **绝不自动付费**：V7 默认全部离线。未获用户单独授权，不运行真实模型付费矩阵，不擅自扩展 24 图真实 API 实验，不重新登记已关闭的账本。
- **不能靠作弊改善测量**：禁止泄漏隐藏真值、未来事件、最优路径、未解锁证据；不能针对 MiMo 的已知错误修改胜负条件；提示词仅澄清公开接口，不能暗示答案。

## 2. 分层指标架构（全图统一基础设施，但非统一得分）

### 2.1 四类指标，不允许相互替代

- **结果 outcome**：成功/失败/部分完成/预算截尾/接口故障，记录原始胜负谓词和时间点；失败要有可审计原因码。
- **能力 primary**：每图预先指定 1–2 个最贴合构念的主要连续指标，说明单位、方向、分母、计算窗口、适用前提、边界与空值；不得因观察到结果再挑最显著的指标。
- **安全/约束 guardrails**：碰撞、错误封堵、氧气耗尽、误指控、超温等按地图分别定义，不能靠效率收益抵消重大违例。
- **过程/成本 diagnostics**：有效动作率、重复无效动作、阶段偏离、资源曲线、token、请求数、墙钟、费用。过程指标不自动等于能力本身。

### 2.2 统一 trace 与计分器契约

每步事件建议字段：`run_id, map_id, instance_id, world_style, nominal_level, scenario_hash, rules_version, agent_condition, seed, tick_before, tick_after, action, action_valid, public_observation_hash, private_state_hash_for_offline_only, event_type, resource_deltas, constraint_violations, milestone_events, terminal_status, stop_reason, usage`。`private_state_hash` 仅限离线裁判，不得进入 Agent prompt、公开日志或模型工具响应。原始证据单独安全存放，敏感信息不可在报告中泄露。

每张图编写 `MetricSpec`：`metric_id`、构念、单位、优化方向、分母与适用样本、计算公式、合法范围、缺失值规则、数据源事件、失败截尾处理、反作弊/对抗测试、手工核对样例。输出 `metric_value` 和 `metric_status`（`valid|not_applicable|censored|unavailable|invalid_trace`），绝不把未观察到的值默认为 0。

**通用派生量**：合法动作率=合法动作数/已提交动作数（分母为 0 则 N/A）；资源消耗=初值−终值+补给量（按事件账本）；最优差=实际可比成本−同一实例同约束的求解器基准（基准不可用则 N/A）；恢复延迟=故障公开可观察时刻至首次有效响应时刻（没有响应且截止则 censored）。若 episode 发生 provider 错误、未知计费或强制停止，能力结果标记截尾而非一律失败。

### 2.3 三种层次的比较

1. **同实例同难度同预算配对**：主要因果对照；固定场景多 seed 只是模型采样重复，不是独立环境实例。
2. **同能力跨场景**：只比较预登记的标准化相对改善或方向一致性，并核查测量等价性；不能把水位与列车延误原值相加。
3. **跨 30 图画像**：按世界/能力/难度展示分项矩阵与分布；默认**不发布单一总分**。若未来必须总分，先冻结标准化、权重、缺失值与安全惩罚，报告敏感性分析和各分项；不得用总体排名掩盖短板。

### 2.4 难度不是长度

对每张地图记录 `D=(可见性, 依赖深度, 事件动态性, 资源耦合, 记忆跨度, 分支复杂度)` 六维设计向量，分别说明提升的维度和不提升的维度。难度的实证校准需要启发式/Oracle/弱模型/强模型的独立基线，不许只按最优步数排序。10 世界 × 3 难度是产品结构，**不是已被统计验证的同尺度量表**。

## 3. 三十张地图的逐图手工指标设计卡

下面每张均是**独立设计候选**：开发者需核对 V4 已冻结的真实规则与观测字段，发现不一致先开 DCR，不能将候选值冒充既有规则。每张至少交付 1 条手算指标样例、1 条合法 Oracle、3 条机制特有失败轨迹、2 条边界轨迹、1 个信息泄漏负例，并写出为什么不等价于同世界其他两图。

### MAP-01｜飞船｜简单｜破损的曙光号

- **测量构念**：前置依赖与电力切换。**不可替代的玩法**：供氧连续性与维修臂争用同一电池，先修补/后供氧不可交换。
- **主要指标（必须逐项实现独立计算，不能只留名字）**：关键依赖满足率=按合法先后顺序完成的必需边数/必需边数；供氧中断最长连续 tick（越低越好）。
- **安全/失败归因**：氧气归零、供氧连续停机>3 tick、非法供电并发分别计数。同时保留成功状态、无效动作、资源轨迹与截尾原因。
- **预登记对照**：同信息量依赖图 vs 自行从配电日志推导；保持电量/路线相同。逐条检查公开信息、初态、规则和预算是否相同；如信息量不同，标记“信息可用性实验”，不能称纯能力提升。
- **难度定位**：只考察少量前置依赖；不得加随机故障伪装难度。
- **本关手工验收焦点**：验证临时断供 3 tick 与 4 tick 的判定分界；修好壳体但未复位动力不能得满分。
- **必须产出的文件**：`docs/v7/maps/MAP-01.md`（含真实规则字段、明确数学公式/单位/分母、两条手算轨迹、能力混淆分析、3 个机制特有失败例、2 个边界例、Oracle/求解状态、至少一个与同世界其他地图不同的机制证明）；`src/.../metrics/map_01.py`（若已有运行时）或 `docs/v7/pending-runtime/MAP-01.md`（设计态，不伪造实测）；`tests/.../test_map_01_metrics.py`（可执行时）。

### MAP-02｜飞船｜中等｜双重警报

- **测量构念**：突发事件下目标重排序。**不可替代的玩法**：第4个有效动作触发泄漏，救人、封存导航核与单向闸门相互牵制。
- **主要指标（必须逐项实现独立计算，不能只留名字）**：事件响应延迟=泄漏首次公开后至首个改变计划的有效动作 tick；双目标完成度=已达成目标权重的明细（不强制合一）。
- **安全/失败归因**：泄漏后继续执行旧目标的无效动作数；船员失压。同时保留成功状态、无效动作、资源轨迹与截尾原因。
- **预登记对照**：突发泄漏 vs 无泄漏；提前预警 vs 现场发现，均共享泄漏位置与合法动作。逐条检查公开信息、初态、规则和预算是否相同；如信息量不同，标记“信息可用性实验”，不能称纯能力提升。
- **难度定位**：动态事件和冲突目标高于 MAP-01，但不以路线长度定义难度。
- **本关手工验收焦点**：必须有“先锁闸导致救援绕路”与“先救人导致导航风险”两种可行/不可行边界。
- **必须产出的文件**：`docs/v7/maps/MAP-02.md`（含真实规则字段、明确数学公式/单位/分母、两条手算轨迹、能力混淆分析、3 个机制特有失败例、2 个边界例、Oracle/求解状态、至少一个与同世界其他地图不同的机制证明）；`src/.../metrics/map_02.py`（若已有运行时）或 `docs/v7/pending-runtime/MAP-02.md`（设计态，不伪造实测）；`tests/.../test_map_02_metrics.py`（可执行时）。

### MAP-03｜飞船｜困难｜最后的百步

- **测量构念**：跨阶段目标保持与早期信息召回。**不可替代的玩法**：五里程碑供电→冷藏→EVA→遥测→航线；K7/校准码早期出现、后期不重复。
- **主要指标（必须逐项实现独立计算，不能只留名字）**：阶段完成覆盖率=完成的合法里程碑数/5；长延迟信息准确率=末阶段提交的早期事实正确数/需提交数。
- **安全/失败归因**：阶段逆序、样本丢失、航线窗错过；区分被截尾和忘记。同时保留成功状态、无效动作、资源轨迹与截尾原因。
- **预登记对照**：完整历史/最近5步/合法外部笔记；保持同一前缀与后续决策预算。逐条检查公开信息、初态、规则和预算是否相同；如信息量不同，标记“信息可用性实验”，不能称纯能力提升。
- **难度定位**：记忆跨度与多阶段依赖共同提高，不强制“100步”作为真实时长。
- **本关手工验收焦点**：设计一个保留码却漏阶段的失败与一个阶段全过但码错的失败，分别归因。
- **必须产出的文件**：`docs/v7/maps/MAP-03.md`（含真实规则字段、明确数学公式/单位/分母、两条手算轨迹、能力混淆分析、3 个机制特有失败例、2 个边界例、Oracle/求解状态、至少一个与同世界其他地图不同的机制证明）；`src/.../metrics/map_03.py`（若已有运行时）或 `docs/v7/pending-runtime/MAP-03.md`（设计态，不伪造实测）；`tests/.../test_map_03_metrics.py`（可执行时）。

### MAP-04｜灯塔｜简单｜潮汐密道

- **测量构念**：周期时间窗判断。**不可替代的玩法**：潮位周期决定密道通行；观察、等待、过道三种动作机会成本不同。
- **主要指标（必须逐项实现独立计算，不能只留名字）**：窗口命中率=在可通行窗口内尝试穿越数/穿越尝试数；最早安全通过延迟=实际穿越 tick−最早可行 tick。
- **安全/失败归因**：高水位闯入次数；被困/回退损失。同时保留成功状态、无效动作、资源轨迹与截尾原因。
- **预登记对照**：公开周期表 vs 通过观察推断周期；不得直接给下一安全 tick。逐条检查公开信息、初态、规则和预算是否相同；如信息量不同，标记“信息可用性实验”，不能称纯能力提升。
- **难度定位**：单一周期机制，无跨设备耦合。
- **本关手工验收焦点**：在窗口刚开启、刚关闭和整周期等待三种边界各给手算轨迹。
- **必须产出的文件**：`docs/v7/maps/MAP-04.md`（含真实规则字段、明确数学公式/单位/分母、两条手算轨迹、能力混淆分析、3 个机制特有失败例、2 个边界例、Oracle/求解状态、至少一个与同世界其他地图不同的机制证明）；`src/.../metrics/map_04.py`（若已有运行时）或 `docs/v7/pending-runtime/MAP-04.md`（设计态，不伪造实测）；`tests/.../test_map_04_metrics.py`（可执行时）。

### MAP-05｜灯塔｜中等｜三束信号

- **测量构念**：共享电力下多窗口排程。**不可替代的玩法**：三次信号各有独立发射窗口、校准先后和功率争用。
- **主要指标（必须逐项实现独立计算，不能只留名字）**：有效信号数/3；窗口利用率=实际完成窗口任务数/可完成窗口任务数；设备空闲可避免 tick。
- **安全/失败归因**：功率超配、校准过期、漏发窗口。同时保留成功状态、无效动作、资源轨迹与截尾原因。
- **预登记对照**：时间表结构化 vs 文字叙述（信息量等价），不得暗示发射顺序。逐条检查公开信息、初态、规则和预算是否相同；如信息量不同，标记“信息可用性实验”，不能称纯能力提升。
- **难度定位**：多窗口交错与共享资源高于 MAP-04。
- **本关手工验收焦点**：先用枚举/求解器证明所有三束在原规则下可行；复核历史 DCR 与修订版本，若不可行则暂停。

### MAP-06｜灯塔｜困难｜暴风眼

- **测量构念**：不确定天气下风险敏感信息获取。**不可替代的玩法**：天气观测有成本与误差；发射/出行在风暴临界区存在损失风险。
- **主要指标（必须逐项实现独立计算，不能只留名字）**：风险调整成功率：分别报告任务达成率与暴露风险，不混为单分；信息价值=有观测与无观测条件下的预登记损失差。
- **安全/失败归因**：高风险窗口行动、资源耗尽、灾害暴露时间。同时保留成功状态、无效动作、资源轨迹与截尾原因。
- **预登记对照**：同天气轨迹配对“可做天气观测/不可观测”；控制额外动作预算。逐条检查公开信息、初态、规则和预算是否相同；如信息量不同，标记“信息可用性实验”，不能称纯能力提升。
- **难度定位**：部分可观测和不可逆风险高于 MAP-05。
- **本关手工验收焦点**：设计两条相同天气不同观测的轨迹，验证行动选择因信息而变而非泄漏未来天气。
- **必须产出的文件**：`docs/v7/maps/MAP-06.md`（含真实规则字段、明确数学公式/单位/分母、两条手算轨迹、能力混淆分析、3 个机制特有失败例、2 个边界例、Oracle/求解状态、至少一个与同世界其他地图不同的机制证明）；`src/.../metrics/map_06.py`（若已有运行时）或 `docs/v7/pending-runtime/MAP-06.md`（设计态，不伪造实测）；`tests/.../test_map_06_metrics.py`（可执行时）。

### MAP-07｜深海｜简单｜逆流阀门

- **测量构念**：阀门干预的因果方向推理。**不可替代的玩法**：阀门开闭改变相邻舱压与流向，局部改善可能造成远端恶化。

- **安全/失败归因**：无证据指控、引用未解锁事实、deadline 截尾。同时保留成功状态、无效动作、资源轨迹与截尾原因。
- **预登记对照**：完整历史/最近5步/合法案卷；同前缀配对且事实可见性一致。逐条检查公开信息、初态、规则和预算是否相同；如信息量不同，标记“信息可用性实验”，不能称纯能力提升。
- **难度定位**：长跨度记忆+证据组合高于 MAP-29；V6 full-history 结果不稳定。
- **本关手工验收焦点**：纯召回与完整调查必须分开报告；检查已解锁身份映射在 full/casebook 的公平可见性。
- **必须产出的文件**：`docs/v7/maps/MAP-30.md`（含真实规则字段、明确数学公式/单位/分母、两条手算轨迹、能力混淆分析、3 个机制特有失败例、2 个边界例、Oracle/求解状态、至少一个与同世界其他地图不同的机制证明）；`src/.../metrics/map_30.py`（若已有运行时）或 `docs/v7/pending-runtime/MAP-30.md`（设计态，不伪造实测）；`tests/.../test_map_30_metrics.py`（可执行时）。

## 4. 逐图质量审查：禁止“30 份同一模板”

每张设计卡必须经以下**六项独立人工复核**，每项提交证据而非勾选：

1. **机制唯一性**：与同世界另两图分别写至少 120 字差异，指明不同状态变量、动作因果和不可逆失败模式；仅替换地图名、场景名、数值视为不合格。
2. **指标必要性**：解释为什么该核心指标能测构念、为何通关率不足、什么反例会让该指标产生误导；至少给两个分数不同但通关状态相同的手算轨迹。
3. **数据可计算性**：逐字段定位原始 trace 来源；需要新事件时先定义只读 instrumentation，不得暗改规则。没有运行时只能提交规范和伪数据单元测试，不得声称真实验证。
4. **可解性/最优性**：分别记录可行路线、独立算法下界/最优证明及缺失证明；构造可行解不等于全局最优。MAP-18 尤其不能把 18/18 服务率等同于延误最优。
5. **公平与无泄漏**：对照不能把最优动作、未来事件或隐藏真相送入 prompt；同实例条件对照除预登记处理外必须一致。
6. **难度校准**：简单/中等/困难各有具体增加的认知维度；不能仅延长倒计时或增加空走步数。若旧设计不符，提出 DCR，**不得私改已冻结规则**。

审核者（人）未实际签署前，所有 `review_status` 均保留 `pending_human_review`。DeepSeek 可以完成 `self_review`、`second_pass_check`，但不冒充人工签署。

## 5. 评分工程落地：先六图，后余图

### 5.1 首批六图（已有 V4/V6 运行时）

- **MAP-08**：从 pressure-test 事件推导候选集缩小、信息增益、错误修复和水位风险。实现 2–3 条固定手算 trace 测试；防止把公开候选签名当隐藏真值。
- **MAP-16**：从同步 reservation/occupancy 日志计算站点容量冲突、交换冲突、makespan、BFS 最优差；对“已失败”与“未完成”分别处理 gap=N/A。
- **MAP-18**：从列车/乘客账本计算服务率、累计延误、首次合法改线、故障恢复时间；处理无故障 L1 的 `not_applicable`。先离线验证故障确实约束最优策略，若未约束则 DCR。
- **MAP-22**：从真实已观察图与动作记录计算合法记忆来源、返程最短路差、重复边率；明确 V6 的 `optimal_moves` 是实例相关而非默认 8。
- **MAP-26**：按诊断/错误前缀/回滚/后续修复阶段分别计算；反馈隐藏条件不能假装同信息基线。
- **MAP-30**：纯召回与完整调查分开；从已解锁 evidence、记录条目、Q4 身份、最终指控计算，不得用私有真凶判断模型是否“看到了”某证据。

每图至少写 3 个可计算指标、6 条手工校验轨迹（成功、失败、边界、截尾等），并以测试断言具体数值。旧 V4/V5/V6 runner 行为不变；新增 V7 指标从 trace 离线重算，和在线过程解耦。

### 5.2 其余 24 图（尚未接入可运行 V4 runtime 的关卡）

**V7 首先交付 24 张逐图手工指标卡和指标事件契约，不允许伪造 24 张运行环境或 API 结果。** 运行时后续逐关批准开发，优先挑选机制覆盖不重复的关卡做小规模垂直切片，例如 MAP-05 时间窗口、MAP-12 长期资源、MAP-17 Pareto 调度、MAP-20 冷却网络、MAP-29 证人可靠性；这只是建议，须审计后确定。每次只实现一张，完成 Oracle、边界、手算指标、无泄漏、独立审查后才进入下一张。不得用通用“场景生成器”一口气生成 24 张地图。

## 6. 评测数据与统计规范

- **统计单位**：区分 world、map、instance、difficulty、condition、run、seed、agent/model。固定场景上不同 seed 不能冒充独立地图实例；多次采样可报告重复运行稳定性。
- **主要结果**：逐图逐实例的原始单位、有效分母、N/A 与截尾、paired difference、失败原因；不把不同地图的原始成本相加。每种世界单独展示三个难度，不强求三关单调成功率。
- **预注册**：每图明确主指标、方向、硬约束、主要对照、预算、停止规则、预计样本量；未登记的探索性结果须标明 exploratory。
- **不确定性**：固定 scene 的 3 个模型 seed 不能据此推断跨场景泛化；有多个独立实例后可按实例聚合并报告不确定性，且区分模型随机性与实例随机性。
- **失败归因**：`environment_unsolvable / model_strategy / invalid_action / unsafe_action / resource_exhausted / censored_step / censored_time / provider_error / unknown_spend / metric_unavailable`；对多原因保留事件序列，不强制唯一原因。
- **可视化**：30×（结果、主指标、风险）矩阵、每世界 3 难度分面、同实例配对斜率图、失败类型分布、资源/温度/水位/客流时间曲线；不要仅画一个“30图综合雷达”就宣称科学测量。
- **基线**：Oracle/独立求解器为可解性上界或参考，不代表 Agent；另做合法随机策略、规则启发式、无记忆/无诊断/无规划机制消融。比较应保证预算与公开信息公平。

## 9. 终验收标准（可机器核对 + 需人工签字分开）

**机器验收**：30/30 张**非空且机制特异**的手工指标卡；每卡有主指标公式/单位/方向/分母/缺失处理/反例、至少一个对照、失败归因、两条手算样例；六张可运行地图各至少 3 个指标可计算且有正确性测试；旧 V4/V5/V6 测试不回归；数据无泄漏；全量测试和静态检查真实运行记录；无付费调用、无旧账本改写。

**人工验收（不得由执行模型代签）**：逐张检查机制是否独特、三难度是否有实质性认知差异、指标是否真正测能力而非接口熟悉程度、地图是否有多个合理策略、是否存在隐性最优路径泄漏、是否值得投入真实 API 成本。任何未审阅地图仍 `pending_human_review`。

**停止/退回条件**：30 图卡片有批量换名痕迹；跨地图直接比较原始分数；难度仅改步数；MAP-18 静态调度地板被忽略；MAP-26 通过赠送资源来“修复”；MAP-30 把调查与记忆混为一谈；没有实际运行就写“测试通过”；任何未经授权付费 API。
