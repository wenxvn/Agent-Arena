### Batch 1：30 张地图逐图能力构念审计（最重要，必须人工式逐张分析）

每图至少完成：
1. 核心能力一句话定义，明确什么是成功行为、什么是反例。
2. **核心机制触发路径**：起始状态→必需观察→关键决策→后果→成功/失败；标出哪些动作可能绕过机制。
3. 公开/隐藏信息矩阵：模型知道什么、不知道什么、何时获知；检查 prompt/Observation/action schema 是否足以合法解题。
4. 可解性与可观察性：Oracle 只能证明存在路径；再验证仅凭公开信息是否存在可执行策略（避免 Oracle 偷看隐藏真值）。
5. 任务预算可行性：Oracle 动作下界、合理启发式所需动作、MiMo 决策预算与环境 horizon；检查是否将正常规划误判为预算失败。
6. 指标：逐条确认计算事件、分母、缺失/截尾规则；至少一个**未通关仍有意义的连续主指标**（若不可能，需说明）。
7. 三次 V8 轨迹的逐条归因，列出**首次偏离合理策略的可观测事件**、失败链和替代解释；不能只照抄终止码。
8. 标记：`MEASUREMENT_VALID` / `INTERFACE_BLOCKED` / `BUDGET_BLOCKED` / `RULE_DEFECT` / `CONSTRUCT_BYPASS` / `METRIC_DEFECT` / `INCONCLUSIVE`（可多标签）；附证据定位。
9. 最小可证伪修复方案：旧/新规则、预期变化、反例、回归风险；**无证据不修改**。

输出 `docs/v9/maps/MAP-01-audit.md` … `MAP-30-audit.md`；每图至少引用 2 段真实 Trace 关键事件，若三次轨迹高度相同，说明重复证据有限；不可伪造。

### Batch 5：建立真正独立的策略基线与第二验证路径

每张地图至少提供：
- Oracle：合法可行解；只有证明最优才称最优，隐藏真值只能用于离线可解性证明，不得作为公开策略基线。
- `legal_random`：只根据当前 Observation 选择合法动作，固定独立随机种子，记录 N/A 与失败原因。
- `public_heuristic`：读取与 MiMo 相同的公开 Observation、动作 schema、决策预算；不得偷读 runtime 内部状态或 Oracle 解。
- `no_key_mechanism`：移除/忽略核心能力的对照（如不使用记忆、不诊断、不重规划），前提是保持任务和可见信息公平；无法定义则说明。
- 指标第二验证路径：至少对 30 图每图 **2 个代表性 trace**，由独立手算或独立代码复算主指标与安全指标，不能仅测试与 extractor 同源的 fixture。

**验收**：基线真实执行且结果可重放；公开策略不得读隐藏状态；每张图记录主指标是否能区分至少两种策略，不能区分则报告 `LOW_DISCRIMINATION`，不捏造差异。

### Batch 6：仅对证据充分的地图进行最小修复

- 所有修复先写 `docs/v9/dcr/DCR-XX.md`，包含：原始规则、证据、根因、候选 A/B、选择理由、预期能力构念影响、兼容性、指标变化、回滚方案。
- 修复优先级：**公开动作/反馈与任务说明缺陷 > 明确规则 bug > 不可解/预算错配 > 核心机制旁路 > 指标缺陷 > 难度微调**。
- 对每项修复先新增失败复现测试，再最小改动实现，再运行 Oracle、独立公开策略、原始失败 Trace 回放（如规则变化不可直接回放则标不可比）、泄漏检查与全仓回归。
- **禁止**：为了把成功率改成 30–70% 而随意加资源/加时间；把模型正确失败改成成功；把困难地图改成数值更苛刻但机制不变；偷偷增加隐藏信息；将 V8 Trace 改写成 V9。
- 重大玩法重设计或改变研究构念，标 `requires_user_decision`，不可由执行 Agent 单方宣布“最终定稿”；允许完成候选分支和离线对照。

### Batch 7：MiMo 有界验证（用户已授权）

真实 API 只用于回答 Batch 1–6 尚不能离线回答的具体假设；先注册实验：地图、假设、旧/新条件、模型标识、temperature、seed 支持情况、prompt/scenario/runtime/metric hash、样本数、预算、停止规则、对照方式。

推荐顺序：
1. 先对 3 张机制旁路图及 4–6 张典型地板图做小样本诊断；每个候选变更先 `dry-run` 和 1 次 smoke test。
2. 对确认修复的地图做 **相同实例、相同模型、相同预算** 的前后对照；旧 V8 数据只作历史参考，若 prompt/runtime 不一致则需重新跑 V9 同期对照。
3. 关键对照可用 3 次重复，预算不足则优先覆盖不同失败类型，而不是全 30 图无差别再跑 90 次。
4. 不允许用“试到成功为止”筛选结果；所有失败、截尾、provider 异常与费用完整保留。
5. 若模型不支持可生效 seed，记录 replicate_id，不伪称 3 个独立 seed；若需场景多样性，另设计真正不同的 instance seed 并先证明同难度、同构念。

费用门禁：独立 V9 append-only ledger；¥10 硬上限，单次调用请求前预留，未知费用立刻停机；provider 错误按预注册有限重试；全部使用真实 usage。`V8` 的账本和 90 局不允许改动。

### Batch 8：能力区分度与阶段总结

每图报告：V8 三次原始结果、失败首因、机制触发覆盖率、Oracle/随机/启发式/消融的主指标分布、连续指标的缺失/截尾比例、定标状态、修复与否、V9 验证结果及可信度。
